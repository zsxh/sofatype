## 目标

候选栏高亮只表达遥控器焦点态：无焦点时无任何 chip 高亮（含首候选）；焦点进入候选行后仅焦点 chip 高亮；焦点移出候选行后高亮消失。空格选首候选行为不变。

## 改动

- `SofatypeImeService.kt` 候选 chip 装载：取消首候选（chip 0）常亮高亮绑定；焦点态样式不变（`accent-wash` 底 + `border-accent` 描边，沿用既有 Token）。
- 展开行 chips 本就无常亮高亮（T11 口径），不受影响；「更多⌄」入口焦点态不变。

**实际实现（2026-11-06）**

- `app/src/main/java/com/sofatype/ime/SofatypeImeService.kt`：
  - `bindCandidates` 首行 chip 0 的常亮高亮实参（`index == 0`）移除；`createChipView` 删除 `baseHighlight` 参数（首行 / 展开行统一无常亮高亮）；`applyChipAppearance` 删除 `highlighted` 参数，高亮判定仅剩 `isFocused`（焦点态底形 `bg_chip_highlight` = accent-wash + border-accent 与文字色 Token 不变）；
  - 注释同步：进入候选行落点描述、chip 外观函数说明改为决策 30 口径（高亮仅焦点态）。
- `app/src/main/res/layout/ime_keyboard.xml`：候选栏注释改决策 30 口径（原「首候选高亮」描述废止）。
- `app/src/main/res/drawable/bg_chip_highlight.xml`：注释改焦点底口径（drawable 本体不变，Token 不变）。
- 单测：全量重跑无既有用例依赖首候选常亮口径（app 模块单测均为纯 Kotlin 模型测试，不涉及视图层高亮绑定），无断言修订。
- `CandidateChips.kt` / `CandidateRow.kt` / `CandidateMoreRow.kt` / `ChineseComposer.kt` 模型未动；空格/OK 选中行为代码路径未动。

## 原因

2026-11-06 户主拍板（决策 30）：首候选常亮高亮与焦点态同形、易被误读为已选中；「只有被选中的才能被高亮」。
