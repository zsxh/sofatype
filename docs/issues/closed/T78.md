## 目标

已连接态 BACK 保活收起后，用户在宿主编辑框间 DPAD 切换焦点（多输入框表单自然手势）不再误杀远程会话：切框沿自动重显远程（T74/T17 重入路径，行为保留）发生后，下一发 OK 不得命中【退出远程】按钮；会话、缓冲与连接代号全程保持，「退出远程」仍只能经显式意图触达（决策 50 显式退出通道不变）。

## 改动

<!-- 开工后按实际实现更新为事实清单 -->

修复口径已拍板（2026-11-16 户主拍板，随决策 64 入册）：**方向 B = 重显沿焦点策略调整**——保活重显时默认焦点不落【退出远程】（保持收起前焦点态或无默认焦点），首发 OK 不触发退出；「退出远程」仍可 DPAD 导航到达。方向 A（保活分支开抑制窗拦切框 show）一并评估后未选用。

2026-11-16 Round 1 实际改动清单：

- 新增 `app/src/main/java/com/sofatype/ime/remote/RemoteReentryFocusPolicy.kt`：保活收起后重显沿默认焦点决策纯模型（纯 Kotlin，无 Android 依赖）——`onKeepAliveHide()` 置位 / `onExplicitWake()` 清除 / `resolveOnShow()` 一次性消费（NONE = 无默认焦点、EXIT_BUTTON = 默认持焦）/ `reset()` 远程模式退出沿复位。
- `app/src/main/java/com/sofatype/ime/SofatypeImeService.kt`：
  - BACK `HIDE_KEEP_ALIVE` 分支（`RemoteBackPolicy` 分流判定零改动）：收起沿新增清除视图焦点 + 暂抑「退出远程」按钮聚焦性（`isFocusable` / `isFocusableInTouchMode` 置 false）+ 策略置位。落窗沿框架会对触屏模式首个可聚焦视图自动赋焦（模拟器 tap 通道实测在案、时机在框架内部），不可聚焦使重显沿无默认焦点为结构性保证、与输入通道无关。
  - `onStartInputView` 远程分支：原无条件 `remoteExitButton.requestFocus` 改经 `resolveOnShow()` 裁决——保活重显沿跳过聚焦请求（新增 trace `keep-alive re-entry -> no default focus（决策 64）`）；其余沿（首次进入 / 显式唤起）维持既有默认持焦并先恢复聚焦性。
  - 隐藏态确认键分支（唤醒护栏）：`requestShowSelf` 前新增恢复聚焦性 + `onExplicitWake()`——决策 50-① 显式唤起「退出远程」默认持焦条款接线不变。
  - DPAD 分支新增：远程模式（服务运行中）无焦点态任一方向键 = 恢复聚焦性 + 导航到「退出远程」（trace `focus null <方向> -> remote_exit（保活重显无焦点态导航）`）；键盘态（服务未运行）无焦点维持既有 no-op。
  - `renderMainCardMode`：REMOTE→KEYBOARD 转换沿新增策略复位 + 恢复聚焦性；KEYBOARD→REMOTE 转换沿恢复聚焦性（防御，幂等）。
  - `RemoteBackPolicy` / `RemoteInputServerManager` / 服务与监听链路 / 布局资源零改动。
- 测试：新增 `app/src/test/java/com/sofatype/ime/remote/RemoteReentryFocusPolicyTest.kt`（9 用例：初始态默认持焦、保活置位→一次性 NONE、消费后回默认持焦、重复置位幂等、显式唤起清除、未标记态显式唤起无害、周期复用、退出沿复位）。
- 隐私红线核对：新增 trace 只记键码 / 焦点 tag / 分支事件，不落输入内容；无新增持久化；服务监听链路零改动。

## 原因

2026-11-16 T74 真机复验批次发现（MiTV4 API 23，trace + 截图留证，明细见 `docs/issues/closed/T74.md` 真机复验节、设备档案坑 25）：已连接 BACK 保活收起（该分支不开抑制窗，T74 既有口径）→ 宿主 DPAD 编辑器间切框 → 宿主切框沿 show 请求无 veto 直接重显远程已连接态 → 重显沿【退出远程】默认持焦（决策 50）→ 用户下一发 OK（意图确认/继续输入）`performClick` 命中退出按钮 → 会话拆除、停服（手机收 disconnect tv-exit）。多框表单是 T74 的核心目标场景，「收起 → 切框 → OK」是自然手势，会话误杀直接破坏「多输入框零扫码」交付价值。对照实验：BACK 后直接 OK 走唤醒护栏安全重入（2/2）；编辑器→按钮焦点迁移不触发重显。
