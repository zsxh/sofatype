## 背景

2026-11-23 户主会话拍板立项（口径选「词源治理 + 分级」）。户主反馈：简拼应先命中常用词，其后影视剧词，最后长尾词；现状热词与新闻词压顶，常见且时效性差。

根因（2026-11-23 探针实证，脚本 `reports/dict-quality-probe/probe.py`，不入库）：

1. 机制层：运行时 `DictHotMerge` 对热词频次一律 ×10 并入，引擎纯按频次排序。热词包 9124 条 ×10 后中位频次 42 720；主词库 65 105 条中仅约 370 条频次高于该值。实测简拼候选 top20 中热词占 86%。
2. 词源层：`baidu-realtime-days.txt`（百度实时热搜榜）60 条几乎全为新闻标题片段（如「金价跌势凌厉」「多地为何鼓励」「成功的会晤」），不是词且时效性差；搜狗 scel「网络流行新词」混有人名、影视名、新闻事件词。
3. 词长倒挂：4~6 字长尾热词 ×10 后中位频次 75 190，高于 2~3 字热词的 39 310——越长的新闻短语排得越靠前，与「短小常用词优先」相反。

## 需求与口径

1. 简拼命中顺序目标：主词库常用词 → 短热词（2~3 字，网络流行词 / 影视剧词）→ 长尾词（4 字以上热词）。
2. 词源治理：百度实时热搜榜（`baidu-realtime` 源）停止并入词库；默认构建不再包含该源。源文件与抓取脚本保留供复评，`docs/DICTS.md` 词库档案同步更新。
3. 热词分级：热词条目不再沿用「原始频次 ×10」。按词长分档重写为绝对频次档位，抹平 scel 原始频次差异：2~3 字档、4 字以上档；档位数值实施期评估，验收以口径 1 的排序目标为准（判据：常用词须回到对应简拼候选前排，长尾词不得出现在常用词之前）。
4. 既有行为不回归：全拼查询、整句组合、候选翻页、高频首屏子集装载链（`pinyin_dict_highfreq.bin` 不含热词，维持现状）。

## 方案评估

影响范围（实施前预评）：

- `pinyin/` 模块：`DictHotMerge`（分级 boost）、`HotDictBuild`（词源清单与档位归一化，构建期方案时）、gradle `buildHotDict` 任务源列表。
- 词源文件：`pinyin/dictsrc/hotwords/`（baidu-realtime 退出默认源；`sources.sha256` 同步）。
- 文档：`docs/DICTS.md` 词库清单与体量合计、`docs/HANDOFF.md` 决策速查一行。
- app 装载链（`PinyinEngineLoader`）预期不动；若分级在构建期完成则零改动，运行期方案则 `DictHotMerge` 签名调整。

回归面：热词合并链单测（T96 既有）、SPD1 门禁（`verifyDict` / `verifyHotDict`）、简拼 / 全拼行为、minSdk 23 禁用 API 24+ 集合方法（HANDOFF 坑 16）。

风险与取舍：热词档位数值直接影响「常用词优先」的强度——过高则短热词仍压中频常用词，过低则热词功能弱化；实施期用探针脚本（dz / ll / jx / xyb 等样本）量化后定档，验收断言固化。

实施结论（2026-11-23 dev Round 1，口径 3 取构建期方案）：

- 实现选择：构建期档位归一化。`HotDictBuild` 输出词库行时按词长重写频次列（scel 与注音源两路统一覆盖）；`DictHotMerge` 移除 ×10 加权，热词条目按包内频次原样并入；`PinyinEngineLoader` 仅随签名适配一行调用。
- 档位定档（探针量化）：2~3 字档 2500.0、4 字以上档 300.0。定档依据：2500 低于主词库「打字」2695（搭子居打字邻位）与 dz/ll/jx 头部常用词最低频 8080（动作），高于主词库「下一步」2300（xyb 显眼包保留可命中居首）；300 高于主词库中位频次 207（长尾词仍可命中），低于全部验收样本常用词。
- 取舍：档位写在构建产物内，`hotwords.bin` 即自描述（探针读产物即引擎视角，无需模拟合并规则）；代价是档位调整需重建 `hotwords.bin`（构建期任务，零网络秒级）。源文件保留原始注音频次不动，`sources.sha256` 不因档位变更。
- 边界事实：验收样本中「李勒优」「江小妹」为 3 字词，落入 2~3 字短档（非 ≥4 字长尾档），档位 2500；两者仍排在对应简拼常用词（来了/理论/力量/进行/继续）之后。「侗族文化」「贵州从江警方」为 ≥4 字长尾档 300。
