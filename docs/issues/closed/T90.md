## 背景

2026-11-19，户主拍板两步（渠道：会话）：①「mock 一并处理」——T89 版本升至 0.2.0(2) 后，mock 源锚定 0.1.0(1) 的静态口径失效：`releases-newer.json` tag v0.2.0 与当前版本相等会落「已是最新」，其资产 0.2.0(2) 与工程同版本不满足「versionCode 真递增」验收口径（T46/T47 铁口径）；②方案拍板「占位符参数化」——户主指出版本值应由参数传入控制、不应硬编码 JSON，与 T41 既有 `__HOSTPORT__` 占位符先例（决策 17「更新源可配置不硬编码」）同构。同日户主一度改口「不建档直接实施」，随即撤回，恢复按 T90 建档。

## 需求与口径

1. `serve_mock.py` 加必传参数 `--current-version` / `--newer-version`（裸版本号，不带默认值，不传或非法即拒绝启动）；JSON 响应按请求改写 `__VER_CUR__` / `__VER_NEWER__` 占位符；tag 派生规则 `v<版本>`；`__HOSTPORT__` 机制不变。
2. 两 JSON 改占位符模板：`releases-up-to-date.json` tag = `v__VER_CUR__`（= 当前版本）；`releases-newer.json` tag = `v__VER_NEWER__`；资产名与下载地址随占位符派生（`sofatype-<版本>.apk`）。JSON 字段形状不变（app 侧 UpdateCheck 解析兼容）。
3. `--newer-version` 必须数值真大于 `--current-version`，否则拒绝启动（防传反）；格式校验 `^\d+(\.\d+)*$`。
4. mock APK 重制（不入库，用前放置）：基线包 `sofatype-0.2.0.apk` = 工程 clean 构建 0.2.0(2)；递增包 `sofatype-0.3.0.apk` = init 脚本 `-PmockVersionCode=3 -PmockVersionName=0.3.0` 注入构建 0.3.0(3)，versionCode 真递增；过时 `sofatype-0.1.0.apk`（旧基线产物，新 JSON 不再引用）删除。
5. `tools/mock/github-releases/README.md` 与 `build-incremented-apk.gradle` 注释口径同步（命令示例数值随新基线，注明示例值随工程基线递增时同步）。
6. 只动 mock 工具链（`tools/mock/github-releases/`），不动 app 侧代码、第三方依赖与版本配置。

## 方案评估

- 影响范围：`tools/mock/github-releases/` 五个入库文件（serve_mock.py / 两 JSON / README.md / build-incremented-apk.gradle 注释）+ 两个不入库 APK 产物。
- 回归面：app 侧检查更新逻辑零改动；JSON 字段形状不变；serve_mock 既有行为（`__HOSTPORT__` 按请求改写、APK 限速、404 防穿越）不动，只增占位符改写与启动校验。
- 风险：占位符漏改写会把 `__VER_CUR__` 字面量直送 app——验收用 curl 实测两 JSON 改写结果兜住；真机 `--bind 0.0.0.0` 场景版本改写与 Host 无关，先于发送完成，两场景同一机制。
- 取舍：版本值走启动参数而非解析 `build.gradle.kts`（解析脆弱）；递增包「必须真构建」省不掉（T46/T47 假阳性铁口径），参数化只省「手改 JSON 文本」；README 命令示例仍带具体数值（示例性质，注明随基线同步）。

实际改动清单（2026-11-19 实施）：

## 验收

- 产物核验：两 mock APK 重制后 aapt 双核——`sofatype-0.2.0.apk` = versionCode 2 / versionName 0.2.0；`sofatype-0.3.0.apk` = versionCode 3 / versionName 0.3.0（真递增）。
- 服务行为：起服务（回环、非默认端口）curl 两 JSON——tag 正确（v0.2.0 / v0.3.0）、下载地址 host:port 正确、无 `__VER_*` / `__HOSTPORT__` 残留；`python3 -m json.tool` 合法性通过。
- 启动校验负例：`--newer-version` ≤ `--current-version` 与非法格式均拒绝启动（退出码非 0）。
- 清场：走完停服务，端口无残留（禁止事项 3）。
- 设备侧端到端三态走查不在本 issue（工具刷新；app 链路 T21/T46/T47/T51 已真机验证，下次走查随批次验）。
- 区分口径：本 issue 验收 = 本机构建与服务行为已验证；真机 / 模拟器端到端未验证。
