## 目标

收起→唤起时序在真实遥控时序下可靠（小米电视4）：

1. 「完成」/「下屏」收起后键盘不被宿主重新唤起覆盖（不回弹，输入内容保留）——T12 户主复验问题 1（fail：真实遥控按「完成」键盘不消失；注入通道同路径收起成功，时序敏感）。
2. 收起后经 OK/CENTER 唤起不直落初始焦点键（digit_1）直出字符——T12 户主复验问题 5 / review-qa 坑 1（3 次复现）。
3. 唤起后正常输入的首键不被吞（加固不得引入新问题）。

## 改动

按实测改为状态判定加固（双抑制窗），时序常量 `HIDE_DELAY_MS=120ms` 保留不动：

- 新增 `ImeShowGuard.kt`：纯 Kotlin 收起-唤起时序守卫（时间由调用方注入，无框架依赖）。
  - 收起抑制窗（Bug A，`SHOW_GUARD_MS=800ms`）：「完成/下屏」收起时开启；覆盖 T12 实测真机 >120ms 的宿主迟到 `showSoftInput`。
  - 唤起抑制窗（Bug B，`WAKE_GUARD_MS=500ms`）：窗口显示沿开启；吞掉首个确认键（唤起键转发副本）后即解除，同窗后续确认键放行。
- `SofatypeImeService.kt` 接线：
  - `hideSelfAfterKeyDispatch()`：收起同时 `onHideRequested` 开抑制窗（保留原 postDelayed 120ms 收起）；BACK 路径不开窗（真实遥控 BACK 收起已 pass，且 BACK 后快速唤起是正常流）。
  - `onShowInputRequested(flags, configChange)`（API 34 双参签名）：收起抑制窗内拒绝显示请求——第一层，不落窗无闪现。注意 API 23 真机为单参签名、无此覆写点（compileSdk 34 下无法调单参 super），由第二层兜底。
  - `onWindowShown()` / `onWindowHidden()`：服务层自跟踪窗口可见性跳变沿（API 34 实测会话更新会重复回调 `onWindowShown`，不能直接当跳变沿）。真实显示沿：收起抑制窗内立即 `requestHideSelf(0)` 复位——第二层，覆盖 API 23 无裁决覆写点的迟到显示；同时开唤起确认键抑制窗。
  - `onKeyDown` 确认键分支两道吞键：① 输入窗隐藏态确认键吞掉不落键面（模拟器 API 34 隐藏态键事件仍路由进 IME，残留焦点键会被隐形触发；真机 API 23 隐藏态收不到事件，本道对其无副作用）；② 唤起抑制窗内首个确认键吞掉并即解除。方向键与打字键不受抑制，唤起后立即可用。
  - trace 新增结构化日志点：显示请求拒绝 / 兜底复位 / 吞键（隐藏态、唤起副本）/ 输入会话起点 / 窗口显示沿；只记键码、焦点 key id、flags 等结构信息，不含输入内容。
- 新增 `ImeShowGuardTest.kt`：11 项单测锁定双窗边界与吞键语义（未开窗恒否 / 窗内拒绝 / 到期放行 / 重复收起刷新 / 吞一次即解除 / 双窗独立 / 重显重开窗）。

模拟器自测（API 34，2026-11-08）：收起链路 OK 后宿主迟到 show 请求实测 141ms / 43ms 到达，均被第一层拒绝，`mInputShown` 持续 false、内容保留；收起后单发/双发 CENTER 唤起均弹出键盘、字符零直出（两层吞键 trace 齐全）；唤起后确认键放行与快速连按正常（双发 `23 23` 四键全落）。详见验收节。

## 原因

T12 户主真实遥控复验发现「完成不收起」（Round 1 fail 项）与「OK 唤起直落字符」同族——收起与宿主唤起的时序竞争；HANDOFF 坑清单「120ms 时序常量真机待复核」实锤。户主 2026-11-08 拍板立项，并作为 T12 Round 2 打回修复项。
