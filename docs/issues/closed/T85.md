## 目标

消除中文模式首键候选刷新的词库加载尖峰：服务就绪后用户首次按键即 ≤ 200ms 出候选（PRD 性能预算口径），不再出现约 1.1 秒的一次性卡顿；稳态刷新性能不回归（T83 实测 14–85ms）。

## 改动

### 现状与根因（T83 真机复验实测 + 户主补充观察，2026-11-18）

- `SofatypeImeService.pinyinEngine` 为 `by lazy`：首次中文按键触发 SPD1 词库加载（65 105 条词条解析 + 全拼串 / 首字母串派生 + 26+416 桶构建），MiTV4 硬件实测首键 `elapsedMs=1105`；后续稳态 14–85ms。
- 模拟器（M1 Mac）同口径首查仅 103ms——尖峰为老硬件加载成本，模拟器走查不可复现，必须真机验收。
- **根因修正（2026-11-18 户主澄清）**：户主反馈慢的场景**不止进程首次加载**——切换到其他 app 后弹出的键盘首键同样慢。原「进程内一次性懒加载、只慢一次」的判断**当时误判、经户主使用反馈纠正**：与设备档案在案的 MiTV4 清杀行为吻合（TvMgr-MemoryAutoClean 周期性 SIGKILL 后台应用，后台化约 10 秒即杀）——键盘收起后 IME 进程后台化即被清杀，下次弹键盘 = 进程冷启 + 词库懒加载从头再来，体感为「经常慢」。
- 根因二分待开工时真机取证：换 app 弹键盘场景抓 pid 与 `onCreate` / 首键 trace，量化进程冷启频度与加载窗口期（弹键盘到首键的可用预热时间）。

### 真机取证结论（2026-11-18，dev 取证、证据 `screenshots/T85/logs/`，gitignore）

- 两场景首键实测：冷启首键 `elapsedMs=1025`（pid 10827）、换 app 弹键盘首键 `1049`（pid 10977）；同进程热重显对照仅 `27`（同 pid 10977）——慢**只**发生在冷启后首次加载，键盘重弹本身无开销。加上 T83 在案 1105ms，全距 1025–1105ms。
- 冷启频度：本轮换 app 回弹键盘 3 次全部命中新进程；进程存活窗 14.6s–4min+ **可变**，且**窗口显示态闲置 ~1–4 分钟也会被杀**（含组合态活跃 51s 被杀样本）。「后台化约 10 秒即杀」原口径（源自设备档案）经本轮取证修正为「后台 / 闲置数秒至数分钟可变清杀，含显示态」——原口径当时依据设备档案在案记录，非误判，系本轮取证补充新形态。
- 预热窗口：tap→键盘窗口可见 ~330–450ms；用户首键最坏 ~0.5–1s < 加载 ~1030ms ⇒ 方向 A 单独不达标实锤。现状闲置期零预加载（窗口显示 12.4s 后首键仍 1049ms）。
- 加载耗时分解为量级推断（解析+派生+建桶 CPU 密集占大头，~10× 弱核差距；IO 未实测）；真实用户首键分布未测；冷启采样 2+1 样本，规模小，如实标注。
- **交叉发现**：隐藏态 OK 分支真机必崩（`requestShowSelf(int)` API 23 不可达，10 次真实使用 FATAL 在案），每次崩溃制造一次冷启、放大本任务尖峰频度——已立项 T86（open，户主拍板暂缓处理）。

### 候选方向（开工前拍板，记录待评审；经根因修正后 B / C 权重上升）

- A. 进程级预加载：Application / IME 服务建立时后台线程加载词库（StrictMode 口径：磁盘 IO 不落主线程）。短板：进程频繁冷启时，进程创建到用户首键的窗口期可能盖不住 1105ms 加载——单独使用大概率不达标。
- B. 加载提速（SPD2 预置派生结构 / 解析优化）：全拼 / 首字母串与倒排桶构建期做掉，加载仅剩 IO + 数组填充；或 mmap / 整块读后单遍解析，压缩对象分配与 GC。目标把加载本身压到 ≤ 200ms 量级。
- C. 高频分段加载：词库拆「高频子集（数千条，加载 ≤ 100ms 量级，首键即用）+ 全量（后台线程补齐）」，加载耗时与词条数近线性估算可行。
- 组合口径：C 或 B 保证冷启首键达标，A 作为进程存活期的常规保障；内存代价（引擎常驻约 3–4MB 堆）真机复核。
