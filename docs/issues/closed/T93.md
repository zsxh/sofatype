## 背景

## 需求与口径

1. **命名自描述**：测试工具目录、脚本文件名、命令入口、Kotlin 测试类名不以 T 编号命名，从名字可见功能。映射表：
   - `tools/t91/` → `tools/integration/`；`t91_runner.py` → `integration_runner.py`；`t91_phone.py` → `phone_driver.py`
   - `tools/t92/` → `tools/perf/`；`t92_sample.py` → `perf_sample.py`；`t92_report.py` → `perf_report.py`；`jmh_to_baseline.py` 名称不变
   - `app/src/androidTest/assets/t92/` → `app/src/androidTest/assets/perf/`
   - Kotlin 类：`T91Harness` → `IntegrationTestHarness`、`T91InstrumentedScenarioSuite` → `InstrumentedScenarioSuite`、`T92PerfBudgetTest` → `PerfBudgetTest`、`T92PerfSupport` → `PerfSupport`（文件随类改名；仅 androidTest 源集，不进 release 产物）
2. **结果目录迁移**：集成测试与性能回归的报告 / 产物输出从 `screenshots/` 迁至仓库根 `reports/`（`reports/integration/`、`reports/perf/`），报告文件名同步去 T 编号（`integration-report.md` / `perf-report.md`）；`reports/` 为生成物不入库（.gitignore）。`screenshots/` 语义不变，仍为走查截图留证目录（AGENTS 截图条款不受影响）。
3. **README 面向外部读者**：根 README 测试节写编译构建测试的操作指引，不出现 issue 编号叙事；内部治理措辞（批准 / 拍板等）中性化，细节用指针指向 tools README。
4. **文档同步**：两份 tools README 的路径 / 脚本名 / 输出目录全文更新；`docs/HANDOFF.md` 代码接入速查指针更新。closed issue（T91 / T92）冻结不追溯，其文内旧路径属历史留证。
5. **验证口径**：全量构建 + 单测（`--rerun-tasks`）全绿；`perf_report.py --selftest` PASS；全部迁移脚本 `py_compile` 通过；`integration_runner.py --stage mitv4-plan`（只打印不触设备）干跑正常；如条件允许做模拟器 instrument 冒烟（不可行则如实标注未做）。
