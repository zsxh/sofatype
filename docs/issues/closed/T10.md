## 目标

中文拼音输入可用：中 / 英切换、组合态候选、选词上屏。S1 场景可完整走通。

## 改动

**app 模块（`app/src/main/java/com/sofatype/ime/`）**

- 新增 `ChineseComposer.kt`：中文组合态状态机（纯 Kotlin，无 Android 依赖）。组合串恒小写、上限取引擎 `MAX_INPUT_LEN`；候选产出经查询函数注入。
- 新增 `CandidateChips.kt`：候选 chip 可见数计算（纯函数，按测量宽度 + 间距 + 可用宽度截断；「更多⌄」展开属 T11，不做）。
- 新增 `CandidateRow.kt`：候选行行内焦点移动模型（纯 Kotlin；左右移动、行缘/行顶不动、向下出行）。
- `SofatypeImeService.kt`：
  - 新增语言模式（默认中文，PRD 5.2「弹出键盘（中文 · 小写）」口径）；「中/英」键切换，切换前组合串以字母形式原样上屏；
  - 中文模式字母键进入组合（组合串经 `setComposingText` 上屏显示）；数字/`.com`/`@` 直出不受语言模式影响；
  - 空格 R-2：有候选选首候选（`commitText` 覆盖组合区域）、无候选时组合串先上屏再输入空格、英文模式直出空格；
  - 删除键组合态内删组合串末位并刷新候选，组合态外维持既有宿主删除行为；
  - 候选栏装载（`refreshCandidatesBar`/`bindCandidates`）：栏区显隐 = 字母键盘 × 中文模式；chips 仅组合态有候选时装载，先测宽后按 `CandidateChips.fitCount` 截断；
  - 候选 chip 视图：可聚焦、OK 选中上屏、首候选高亮（`bg_chip_highlight` = accent-wash 底 + border-accent 描边 + accent-text 文字；普通 chip 无底色 + 键帽字符正文色）；
  - 方向键分层路由（`onKeyDown`）：键盘键走 FocusNavigator 格网，chip 走 `CandidateRow` 行内语义；行 1 键 UP 且候选可见时进入候选行（落点 chip 0），DOWN 出行回进入前键位（丢失时回初始键）；
  - 选中候选后焦点回归：焦点原在 chip 上才回归键盘键，键盘键上的焦点不动；
  - 拼音引擎懒加载（assets `dict/pinyin_dict.bin`），加载失败降级为无候选（不崩溃）；
  - 英文/数字/符号键盘：候选栏 GONE + 键盘区顶部边距清零（上移占满主卡片）；进出符号键盘先结束组合态；完成键结束组合态后收起。
- `app/build.gradle.kts`：新增 `implementation(project(":pinyin"))`；`mergeDebugAssets` 显式依赖 `:pinyin:buildDict`（app 依赖 pinyin 后两模块同图构建，Gradle 隐式依赖校验要求该依赖边）。

**app 资源**

## 踩过的坑

1. 未挂载的测量用 `TextView` 未设 LayoutParams：`setText` 触发 `checkForRelayout` 解引用空 layoutParams → NPE，IME 进程崩溃（系统自动重启服务恢复，未阻塞宿主）。修复：测量前显式设 WRAP_CONTENT LayoutParams。模拟器走查实测发现。
2. app 依赖 `:pinyin` 后，`mergeDebugAssets` 消费 `pinyin/assets`（convertDict 输出目录）触发 Gradle 隐式依赖校验失败 → `mergeDebugAssets` 显式 `dependsOn(":pinyin:buildDict")`（附带保证合并前产物已过门禁并就绪）。T9/T30 时期 app 未依赖 pinyin、两模块不同图，故未暴露。
3. 走查期间注入通道丢键事件多次复现（HANDOFF 坑 4）：DPAD UP 一次丢失导致焦点路径与预期不符；改用 ImeKeyTrace 逐步校验 + 失败重试后走查完成。
4. 候选行进入口径：仅行 1 键 UP 进入候选行（栏区在行 1 上方）；行 2/3/4 UP 按格网移动，需先到行 1 再进候选行。走查实测确认路径符合视觉行列关系（FR-A11 不跳变）。
