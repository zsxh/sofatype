## 背景

2026-11-24 户主会话拍板（非 API 方案调研后三点拍板）：①采纳「Atom 检查 + 构造下载 + 代理前缀」架构并**移除真实 API 依赖**（T102 的 api.github.com latest 通道移除，mock JSON 兼容保留）；②设置页用户可选更新是否走 gh-proxy.com 代理，**默认开**；③mock 补 Atom 形状模式。动机：后续可能需经 GitHub 加速代理访问（api.github.com 子域代理支持差、且匿名有限流；github.com 网页路径为 gh 代理的本职支持范围）。

调研实证（2026-11-24）：`releases/latest` 302 直连 Location 含版本号但经 gh-proxy.com 被吞（返回 200 HTML）→ 不可靠；`releases.atom` 直连与经 gh-proxy.com 均可达（200，含 tag 与全量说明）；构造下载 URL `releases/download/<tag>/sofatype-<版本>-unsigned.apk` 经 gh-proxy.com 实测 200 且字节数与真包精确一致。

## 需求与口径

1. **检查源**：默认 `https://github.com/zsxh/sofatype/releases.atom`（真实源），取首个 entry（feed 新到旧排序）＝最新发布；`update_endpoint_url`（api.github.com latest，T102）移除，资源名改 `update_atom_url`。
2. **下载地址**：不从 feed 解析，按 T100 资产命名口径构造——`releases/download/<tag>/sofatype-<去 v 版本>-unsigned.apk`，并应用代理前缀。
3. **代理前缀**：设置页检查更新行内复选框「gh-proxy.com 加速」，默认勾选；SharedPreferences 持久化（key `proxy_enabled`，默认 true）；关闭 = 直连。
4. **mock（debug）**：`UpdateMockReceiver` 注入通道扩展 `EXTRA_ATOM`（`--ez atom true`）→ 覆写为 mock URL + Atom 模式；`serve_mock.py` 支持 `.xml`（Atom 形状 + 占位符改写），新增 `releases-atom.xml`。JSON 数组 mock（releases-newer / up-to-date）保持不变，仍走「检查 → 发现新版 → 下载态」全链。
5. **说明呈现**：Atom content（HTML 转义）清洗为纯文本后入 UI（既有 updateNotes 控件）。
6. **T102 关系**：T102 以「被本 issue 取代」关闭；其产出的解析器数组形状兼容、latest 单对象兼容能力、单测与注入通道扩展保留并入本架构。

## 方案评估

预评（实施前）：

- 影响范围：update 包四文件（UpdateAtomParser 新增、UpdateCheck 配置化、UpdateEndpoint 聚合配置与代理偏好、UpdateMockReceiver 扩展）、strings / layout / dimens、SettingsActivity 接线、单测三个文件、mock 两文件、文档两处。HTTP / 下载 / 安装通道零改动。
- 回归面：debug JSON mock 全链（检查 → 发现新版 → 下载 → 安装）不回归；失败态 UX 不变；EMPTY_ENDPOINT / CHECK_HTTP / CHECK_NETWORK / PARSE / NO_APK_ASSET 失败语义不变。
- 风险与取舍：
  - Atom 为 GitHub 网页侧功能（非 API 契约），长期实践稳定但非承诺级；
  - gh 代理站可用性随时变动 → 前缀做成设置开关（默认 gh-proxy.com），失效用户可关（回退直连，构造 URL 直连本身可达）；
  - 说明为 HTML 转义形态 → 清洗为纯文本（自研规则：实体解码 + 去标签 + 空行折叠）。
