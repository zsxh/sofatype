## 目标

已连接态副卡不再是独立空卡：二维码卡保留，网址行原位换成绿点状态行「已连接 · 设备名」；
配对 token 滚动签发（已连接态展示的码始终是有效新码）；新设备扫码自动顶替旧连接。

## 原因

户主 2026-11-07 重开 T17 口径：决策 32 的独立「已连接」卡面整卡只有一行文字，观感空；
拍板改为二维码卡保留 + 下方状态行，且二维码换滚动新码、新设备上线顶掉旧设备（决策 35）。
几何复核：副卡 548px = 40×2 + 376 + 10 + 22 = 488px，余量 60px，单行状态行（20px 文字 +
8px 圆点）直接放得下，决策 32「配对卡加状态行则二维码容不下」的前提不成立。

## 踩过的坑

1. **`redir remove` 子命令不存在**：正确子命令是 `redir del tcp:<hostport>:<guestport>`；
   写 `remove` 报 `bad sub-command`（本轮实测，DEV-GUIDE 只记了 add 语法）。
2. **闭包捕获自身初始化变量**：工厂 lambda 内 `val session = PairingSession(..., onPaired = { onPaired(session, ...) })`
   自引用编译不过，改 `lateinit var session` 局部变量先声明再赋值（Kotlin 局部 lateinit）。
3. **STATUS 广播取 token 会取到陈旧行**：`logcat -d | grep | tail -1` 可能命中上一轮输出
   （token 已消费），导致配对被拒 4001——取 token 前先 `logcat -c` 或按最新时间戳过滤。
   （首轮 C/D 因此误用过期码，意外实证了死码被拒路径。）
4. **竖向 LinearLayout 子视图默认宽 MATCH_PARENT**（DEV-GUIDE/坑清单未录，T35 回访发现）：
   `addView` 不带显式 LayoutParams 时竖向排列默认子宽 MATCH_PARENT，行内仅竖向居中 →
   整行水平靠左，列 gravity CENTER 形同虚设；视觉走查「大致在下方」不易察觉，像素量测才暴露
   （中心偏差 111px）。教训：需要水平居中的行一律显式 `WRAP_CONTENT`（同文件地址行因 T10 坑口径
   已显式赋参而幸免）。
5. **DEV-GUIDE T3 坑 1 复踩**：`export HOME=... JAVA_TOOL_OPTIONS="-Duser.home=$HOME"` 写在
   同一条 export 里，`$HOME` 展开取旧值 → gradle 落回 `~/.android` 找 debug keystore 报不可写。
   按模板逐条 export 后恢复。已有坑文档再次生效，无新增事实。
