## 目标

## 改动

- 新增 `FocusNavigator.kt`：纯 Kotlin 焦点导航模型。以画板① 键位推导 12 列 × 4 行格网（行内键按 T28 列节奏口径累计 x 原点得列号；完成键按「与图标列左缘对齐」声明占据行 3/4 图标列格位）。导航规则：左右=同行相邻格位、上下=同列相邻格位、表缘不动、完成键以顶行格位为锚。
- 新增 `FocusNavigatorTest.kt`：11 项单测——网格全覆盖、完成键跨行格位、初始焦点、横移同行/纵移同列性质、表缘不动、完成键进入/离开路径、关键路径显式锁定、从初始键全键可达（47 键）、未知键无移动。
- `SofatypeImeService.kt`：
  - 键帽视图可聚焦（含 focusableInTouchMode，保证 `input tap` 后焦点机制可用）；
  - `onStartInputView` 初始焦点落键区左上角「1」；
  - `onKeyDown` 处理 DPAD 方向键（调 FocusNavigator 移焦点，表缘消费不动）；处理 OK/回车（DPAD_CENTER/ENTER/NUMPAD_ENTER 派发焦点键 performClick）；BACK 收起；
  - 「完成」键接线 Done 动作：finishComposingText（组合态插点，T9/T10 前为无操作）+ 收起；
  - 「下屏」收起与「完成」收起经 `hideSelfAfterKeyDispatch()`：postDelayed 120ms（见坑 1）。
- `bg_key.xml` / `bg_key_done.xml`：新增 `state_focused` 态。普通键 = `key_hover` 微高亮底 + `border_accent` 主色描边；完成键 = `accent_wash_strong` 底（既有 Token，零新增色值）。

## 踩过的坑

1. **CENTER 键转发广播双触发**（模拟器 API 34 实测）：框架把转发键事件广播给 IME 与宿主两端。IME 在 `onKeyDown` 处理 OK 并同步 `requestHideSelf` 的同时，宿主 EditText 同拍触发 `showSoftInput`，收起被覆盖、键盘重新弹出。修复：「下屏」「完成」的收起经 `postDelayed(120ms)`（`hideSelfAfterKeyDispatch`），时序常量真机需复核。
2. **DPAD/OK 键事件不经过 IME view 树**：键帽视图的 `OnKeyListener` 与根视图 `OnKeyListener` 均收不到事件（根视图方案无效：ViewGroup 沿焦点链分发）；事件由框架转发直达 `InputMethodService.onKeyDown`。方向键与 OK 必须在 service 层处理。BACK 收起早期实测有效是 policy 层路径，不能作为「事件到达 view 树」的证据。
3. **IME 窗口不持窗口焦点**：`dumpsys window` 的 `mFocusedWindow` 始终是宿主窗口（Gboard 同样如此），键事件经 InputMethodManager 转发机制路由到 IME，排查键无响应时先用 service 层日志定位事件到达点。
