## 踩过的坑

1. macOS JVM（Zulu 17）不按 `HOME` 环境变量推导 `user.home`：沙箱内 `~/.android` 不可写导致 `validateSigningDebug` 失败，只 `export HOME` 无效，须加 `JAVA_TOOL_OPTIONS="-Duser.home=<工作区>/.home"`。
2. nix 客户端 fetcher 缓存 SQLite 在沙箱下只读报错（attempt to write a readonly database）：`XDG_CACHE_HOME` 指进工作区后恢复。
3. `services.gradle.org` 与 `downloads.gradle.org` 网络超时（dl.google.com、repo1.maven.org、plugins.gradle.org 正常），wrapper 无法从官方源引导。改用腾讯镜像。校验和获取方法：从 nix store 沿 deriver 链找到 fetchurl 源构件 derivation，其 `outputHash` 即官方钉死的 zip sha256（权威值，nix 每次构建都会校验），再与腾讯镜像实际下载字节比对一致后写入 wrapper。当前对齐 nix 包（8.14.4）：`f1771298a70f6db5a29daf62378c4e18a17fc33c9ba6b14362e0cdf40610380d`。
4. 沙箱下模拟器不能写真实 `~/.android/avd`：在 `ANDROID_USER_HOME=<工作区>/.home/.android` 内按同规格重建 AVD（tv_1080p / android-34 / android-tv / arm64-v8a），与本机既有 AVD 等效。非沙箱终端不受影响：`nix develop` 后直接 `./gradlew` 即可，debug keystore 落真实 `~/.android`。
5. 清理模拟器时 `pkill -f crashpad_handler` 会误伤户主自己的应用（PixPin / Brave 的同名辅助进程，会自动重启）。下次按 `/nix/store` 路径精确匹配。
6. gradle wrapper 官方源（services.gradle.org / downloads.gradle.org）网络超时，`distributionUrl` 采用腾讯镜像，`distributionSha256Sum` 钉死官方 SHA256 防篡改（权威值提取方法见坑 3）。户主已接受（2026-11-04 拍板）。注意：**wrapper jar 版本取决于执行 wrapper task 的 Gradle 版本，与 distributionUrl 版本可以不同**。版本口径按决策 24（2026-11-04 户主拍板）：wrapper 版本以 nix package 为准，文档不规定 Gradle 版本；重生成时在 flake 环境内跑 `gradle wrapper`（不带 `--gradle-version` 指定版本），jar 与发行版同源于 nix 包当前版本，nix 包升级后随升级重生成。演进记录：首版 jar 由 flake Gradle 8.14.4 生成、发行版钉 8.5（漂移）→ 评审第 1 轮方案 b 改 8.5 双同源 → 决策 24 裁决后重做为 nix 包双同源（当前态）。
