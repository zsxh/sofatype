## 目标

开发工具链收敛到单一 nixpkgs channel（nixos-unstable），全部工具同源可复现。flake devShell 内置 Obscura 无头浏览器（Rust 引擎 / 内嵌 V8 / Apache-2.0），为手机 H5 页（远程输入页）提供 CDP 调试通道：`obscura serve` 起 CDP 端点，Puppeteer / Playwright 经 `ws://127.0.0.1:<port>` 接入调试，替代「借宿主机 Brave」的临时走查通道（原通道不进 flake、跨机器不可复现）。

## 改动

- `flake.nix`：
  - 唯一 nixpkgs 输入由 `github:NixOS/nixpkgs/nixos-26.05` 换为 `github:NixOS/nixpkgs/nixpkgs-unstable`（nixpkgs-unstable channel 的快照分支：纯包集门禁、不含 NixOS 测试，对 devShell 用途与 nixos-unstable 等价；26.05 分支无 obscura 包）。过程备注：初版曾改 channel tarball 形式绕 GitHub API 限流（当时锁定并验证成功），户主复拍板定 github: 分支引用形式后重锁复验；
  - devShell `packages` 增 `pkgs.obscura`，注释与 shellHook 声明 CDP 用法（`obscura serve --port 9222`，默认 `ws://127.0.0.1:9222`，仅监听回环；非回环绑定需 `OBSCURA_CDP_TOKEN` ≥32 字节；本地 / 局域网 H5 需 `--allow-private-network`，默认拦截回环与 RFC1918）；
  - flake description 补 Obscura 项。
- `flake.lock`：重锁 nixpkgs（github:nixpkgs-unstable → rev `6dadaf4375be`，即 nixpkgs-26.11pre1108556 快照），随批提交。
- `local/DEV-GUIDE.md`：工具链说明与 H5 走查通道更新（不提交）。
- 文档联动：`docs/TASKS_20261104.md` T34 行、`docs/HANDOFF.md` 快照 / 决策速查 / 维护约定 5（工具链口径不入 PRD）。

户主拍板（2026-11-07）：所有工具统一 nixpkgs channel 并统一到 unstable；H5 页调试需要可控、可复现的无头浏览器通道。Obscura 仅收录于 unstable 系，nixos-26.05 分支无此包，故整体换钉。

## 踩过的坑

- `github:` 类型 flake 输入**仅在 `nix flake update` 时**调 api.github.com 解析分支头：本机代理出口 IP（共享）限流 403 期间 update 必失败（本任务实测两次）；日常构建 / 他人 clone 走已锁 `flake.lock`，不碰 API、不受影响。403 持续时（a）由可联网侧手动 `nix flake update`（本任务实际做法），或（b）临时改回 channel tarball 形式（`channels.nixos.org/nixpkgs-unstable/nixexprs.tar.xz`）锁定后提交 lock。
- nixpkgs 锁 obscura **0.2.2**，上游 wiki 文档描述 main 分支行为：`--ready-file`、`--font-dir` 在 0.2.2 均不存在（报 `unexpected argument`）；serve 就绪改端口探活。
- 0.2.2 无字体注入能力，**截图中文渲染为方块**（布局 / 表单控件正常）；文字与布局断言走 `Runtime.evaluate` DOM 探针，中文视觉走查仍走模拟器 / 备选浏览器通道。
- `obscura fetch` 位置参数与 `--file` 互斥，混用直接报错；`--eval` 不生效于 `--file` 批模式。
- 本机 TUN 代理环境下外网直连 `fetch` 可能报网络错误（同环境 curl 正常）；项目用途为本地 / 局域网 H5，不受影响。
- nix Gradle 与 wrapper 钉的 8.14.4 出现小版本漂移（channel 期 8.14.6，决策 24「wrapper 与 nix 包一致」随换钉自然漂移）：wrapper 仅 bootstrap 用，日常构建走 wrapper 不受影响；如需重新对齐（重生成 wrapper 三件套），先向户主确认。
- Gradle「incompatible with Gradle 9.0」deprecation 警告为既有现状（wrapper 8.14.4 + AGP 8.2.2），非本次引入。
