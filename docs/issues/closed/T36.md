## 目标

候选刷新 ≤200ms 有精确直测数据：debug 构建补「候选装载完成」trace 埋点，多次采样复测出具数据，报告测量口径与精度。验证口径 = 模拟器（户主 2026-11-08 拍板，范围调整）；真机直测挂账后续真机批次。

## 改动

全部在 `app/src/main/java/com/sofatype/ime/SofatypeImeService.kt`（+61/−5 行，另含 T37 同文件改动见 `T37.md`）：

1. 新增字段 `candidateLoadStartMs`：onKeyDown 到达主线程时刻（`SystemClock.uptimeMillis()`），候选刷新计时起点；`finally` 归位 -1，计时只在本键事件栈内有效。
2. `onKeyDown` 入口落计时起点，键事件正文抽至 `dispatchKeyDown`（处理逻辑不变），`finally` 归位计时字段——导航等不产生候选装载的键事件不留陈旧起点。
3. `bindCandidates` 装载完成处（chips 与「更多⌄」入口绑定后）新增 `traceCandidateLoadCompleted`：经既有 `trace()` 输出（tag `ImeKeyTrace`，`BuildConfig.DEBUG` 门控，release 静默）。行格式：`candidates loaded fromKey=<bool> elapsedMs=<ms> availablePx=<px> firstRow=<n> total=<n> toggle=<bool>`；只记耗时与结构计数，不含输入内容（隐私红线）。`elapsedMs=-1` 表示非键事件触发的装载（键盘重建 / 会话启动等），不计时。
4. 文件头接线注释补 T36/T37 两条。

## 踩过的坑

1. **采样循环须显式复位组合态**：组合态删除键一次只删一位；循环起点组合非空时（如遗留 `e`），OK(e) 实际装载 `ee`（词库恰 2 候选）——trace 呈现 `total=2`，RIGHT 探针也落在 2-chip 行，采样组成漂移。处置：循环起点先删至空组合，每轮「绑定 → 删除复位」闭环。本轮两段被污染采样已弃用（`screenshots/T36/t36-all-binds-raw.log` 留存全过程，清洁段为 `t36-samples-clean.txt`）。
2. **release 行为级静默直测不可行（决策 21 的验证方法边界）**：测试输入区仅 debug 构建显示，release 设置页无可聚焦文本宿主（实测截图 `screenshots/T36/t36-release-settings.png`，tap 后 `mInputShown=false`）；已签 debug 钥匙 release 包装回模拟器实测确认该页面无输入区。release 静默证据改用 dex 方法引用静态核查（见验收第 1 条），属同口径替换。
3. **注入通道两坑（评审补充）**：硬件键码 62 在组合态下是向组合串插空格（R-2 绑定的是空格键面，不是键码 62）；键码 67 在 <1.5s 注入节奏下 IC 更新会丢（≥2s 节奏或每键穿插 dump 同步则 20/20 可靠）。评审采样终版协议=候选提交复位；5 轮失败尝试留痕 `screenshots/T36/qa-sampling-*.txt`。
