## 目标

设置页新增「日志」子项（正式功能，release 与 debug 行为一致），交付三项能力：

1. **开启调试日志开关**（默认关）：只控制文件写入；logcat 通道不动（历轮走查取证链不变）。关闭时后两项置灰不可调，已写文件保留（清空只走查看页按钮，卸载即清）。
2. **日志大小限制**：1/2/5/10 MB 四档，默认 2 MB；超限轮转覆盖保留最新（环形语义），轮转触发自身落一条日志。
3. **查看日志**：只读浏览页——进入定位最新（底部）、上下键滚动、[刷新] 手动刷新、[清空日志] 需确认；无导出（取证走 adb pull）。

入口：设置页「测试打字」下方第四行「日志」按钮（决策 44/47 样式口径），行右侧状态点 + 「调试日志已关闭」默认态。视觉基准：`designs/20261114` 画板 7 修订 / 14 / 15（2026-11-14 出稿、check 通过）。

## 改动

1. **日志组件换 Timber**（`com.jakewharton.timber:timber:5.0.1`，户主明确指令，「纯 Kotlin 无第三方 SDK」约束的指令例外，随 ZXing 先例）：双树 = logcat 树（行为同现状）+ 文件树（开关控制，开启才挂载）。
2. **现有日志点机械迁移**、文案不变：`ImeKeyTrace`（`SofatypeImeService.kt`）31 点、远程服务（`remote/RemoteInputServerManager.kt` TAG + `PairingSession` logEvent）26 点、更新与设置页（`SettingsActivity.kt` UPDATE_LOG_TAG / FOCUS_LOG_TAG、`TestTypingActivity.kt`）15 点。
3. **`ImeKeyTrace` 门控放宽**：`BuildConfig.DEBUG` → 「debug 构建 或 开关开启」（release 开关即记键控轨迹）。
4. **文件写入组件**（新，纯 Kotlin）：私有目录单文件 `filesDir/logs/`、专用线程异步写 + 行缓冲（不落主线程）、超档位轮转覆盖保留最新、写失败降级不崩。
5. **新增日志点**：开关切换、轮转触发、清空动作、写失败降级、IME onCreate/onDestroy、未捕获异常栈（写入文件后交回系统默认处理，崩溃行为不变）。
6. **UI**：`SettingsActivity.kt` 设置卡第四行「日志」入口 + 日志子页（开关 / 档位 / 查看入口）+ 查看日志页（浏览 / 刷新 / 清空确认）；遥控焦点路由沿设置页既有 pre-IME 分路（T54/T59/T67 口径）；无障碍标注齐全。
7. **持久化**：SharedPreferences 存开关与档位（仅配置项）——T27「全源集无持久化 API」审计口径随之失效，本 issue 即如实记录（不涉输入内容，红线不破）。
8. **隐私守卫单测**：既有「事件日志无输入内容」用例扩到文件树——文件日志零输入内容 / 组合串 / 候选词 / 远程文本 / deviceName；token 仅出现在服务启动 / 重建行配对地址（T27 拍板不打码）。

## 原因

真机问题排查需要现场日志；现行日志只在 logcat，依赖 adb、不面向用户。开关默认关 + 私有目录 + 轮转上限，把磁盘与隐私面压到最小。

## 踩过的坑

1. **异步读取未完成时截图取证会拍空**（2026-11-15 Round 2 review-qa 勘误自证，勘误 Round 1 一处证据判读）：查看页统计行/浏览卡内容为后台线程异步读取，截图时机早于加载完成会拍到「共 0 行 · 0 MB」初始空态（layout 初值 `log_empty_stats`）——走查取证须在页面数据加载完成后截图/dump，勿以空态截图断言读取缺陷；Round 1 B1 的布局遮挡结论（bounds 铁证）不受此影响，Round 2 复验读取链正常。清空后统计行瞬时读「共 0 行」而文件已有 1 行清空日志点，为 300ms 行缓冲窗内读取，刷新即一致，非缺陷。
2. **清空确认框按钮方向勘误**（2026-11-15 真机复验，勘误 Round 2 模拟器一处记录）：真机确认为标准 AlertDialog 双钮——取消在左（button2）、清空在右（button1），焦点默认取消；取消 → 清空走 **RIGHT**（LEFT 无处可移，线性焦点导航预期）。Round 2 模拟器记录的「左移选清空」方向在真机布局下不适用，交互行为等价、非缺陷。
