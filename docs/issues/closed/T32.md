## 原因

T10 接线时的依赖边只匹配了 debug 变体名（`app/build.gradle.kts` `tasks.matching { it.name == "mergeDebugAssets" }`）。app 的 assets 源目录指向 `pinyin/assets/`（`convertDict` 的声明输出目录），debug / release 变体共用；release 的 `mergeReleaseAssets` 无依赖边，而 `convertDict` 经 `:app:compileReleaseKotlin → :pinyin:jar → :pinyin:processResources → buildDict` 侧门进入 release 任务图，触发 Gradle 8 隐式依赖校验失败：

```
Task ':app:mergeReleaseAssets' uses this output of task ':pinyin:convertDict'
without declaring an explicit or implicit dependency.
```

2026-11-07 lead 复现两次：① 完整 `assembleRelease` 5 秒 BUILD FAILED（上述报错）；② 单跑 `:app:mergeReleaseAssets` 反而 BUILD SUCCESSFUL——`:pinyin` 任务不在图内校验不触发，会把磁盘上既有旧 `pinyin_dict.bin` 静默合并。故修复方向是补齐依赖边，不是绕开校验。T13 评审（review-qa 独立构建）首次暴露；验收口径长期只跑 `assembleDebug + testDebugUnitTest`，故 T10~T13 未发现。

## 踩过的坑

- 坑 1（验证方法）：改动 `app/build.gradle.kts` 后按标准模板跑 `testDebugUnitTest` 仍显示 UP-TO-DATE（测试未实际执行，test-results 还是改动前的 08:19 旧文件），直接引用会拿旧结果当修复后证据。处理：加 `--rerun` 强制实跑再统计 XML 计数。教训：引用测试计数前先核对 `app/build/test-results/` 时间戳。
- 坑 2（口径）：release 产物文件名是 `app-release-unsigned.apk`（未签名口径，无 signingConfig），不是 `app-release.apk`；按后者找文件会扑空。
- 坑 3（验证方法，review-qa 复跑实测）：Gradle `--rerun` 只对紧邻其前的一个任务生效。一条命令 `… :app:mergeReleaseAssets :app:packageRelease --rerun` 只有 `packageRelease` 实跑，`mergeReleaseAssets` 仍 UP-TO-DATE；要强制多个任务实跑，须逐个任务各带 `--rerun` 或分轮执行。
- 坑 4（验证方法，review-qa 复跑实测）：删 `pinyin_dict.bin` 触发重转换后，若新产物与旧产物字节一致，`mergeReleaseAssets`/`packageRelease` 会因输入快照未变而 UP-TO-DATE——构建绿但 merge 并未实际执行，不能当「merge 实跑通过隐式依赖校验」的证据；要强制 merge 实跑，删 `app/build/intermediates/assets/<variant>/` 后重跑 `assembleRelease`。
