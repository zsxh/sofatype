## 目标

长文本删除高效：删除键长按连删，节奏先慢后快。

## 改动

- 新增 `app/src/main/java/com/sofatype/ime/DeleteRepeatRhythm.kt`：连删节奏纯模型（不依赖 Android 类）。节奏口径：首删后初始延迟 400ms；重复间隔自 200ms 分级（25ms 步进）加速至 50ms 下限后恒定。
- 新增 `app/src/test/java/com/sofatype/ime/DeleteRepeatRhythmTest.kt`：锁定节奏值全序列（400 / 200→175→150→125→100→75→50→…）、下限不破、单调不增、按住时间轴前 1s 4 删 / 第 2s 18 删、稳态每秒 20 删、非法参数拒绝构造。
- `app/src/main/java/com/sofatype/ime/SofatypeImeService.kt` 接线：
  - 确认键（OK/回车）按下命中删除键（主键盘 `backspace` / 符号键盘 `delete`，同为 `KeyAction.Delete`）时武装连删排程（`armDeleteRepeatForFocusedKey`），延迟全部取自 DeleteRepeatRhythm；焦点键非删除键不武装（光标移动等其他键无长按重复）。
  - 单击与连删共用删除路径 `performDelete()`（自 execute 删除分支抽取）：中文组合态先删组合串、删空后接删已上屏文本，与单击语义一致。
  - 连删解除点：确认键抬起（新增 `onKeyUp`）、任一新按下（`dispatchKeyDown` 入口）、键盘隐藏（`onWindowHidden`）、服务销毁（`onDestroy` 清排程）。输入会话重开不解除：连删绑定仍在按下的物理键（应用侧注入类文本变更会触发一次性会话重开，绑定会话会误杀长按，见「踩过的坑」2）。
  - 框架键重复事件（ACTION_DOWN repeatCount>0）不消费，节奏不随系统重复率漂移；debug trace 记重复删除计数（不含输入内容）。

## 踩过的坑

1. 模拟器 console 原始键事件通道（`adb emu event send` / `sendevent`，goldfish 设备路径）不达 IME `onKeyDown`（trace 全无）；长按走查必须走 `input keyevent` 注入通道。可控时长按住 = `settings put secure long_press_timeout <ms>` + `input keyevent --longpress 66`（走查后恢复 400）。
2. 应用侧注入类文本变更（如 `adb shell input text`）使 TextView 在下一次 IC 变更时重开输入会话（`onStartInputView restarting=false`，焦点回初始键）；实测纯按钮填充 + 键盘点击路径无此重启。为此连删解除点不绑定会话生命周期（坑 1 的注入通道由此坑强化）。
3. 重装 APK 会杀掉前台设置页进程（logcat「app died」）；装包后必须重新 `am start`，否则后续点击全部落在桌面。本次实测踩中，走查重做一轮。
4. 长按期间分阶段截图受 `adb shell screencap` 冷启延迟（~0.2-0.3s/张）影响会滞后于名义调度时刻；分阶段截图判读以 trace 时间戳为准（三份 logcat 为节奏定量证据）。
