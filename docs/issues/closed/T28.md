## 目标

键盘列间隔恢复画板①口径：spacer 列占位实宽 66px（42px spacer + 两侧 flex gap 各 12px），字母 / 功能 / 图标三列回位，完成键左缘与下屏 / 删除列左缘对齐（同在 x=1228），空格→完成间距回到 12px 标准键距。

## 改动

- `SofatypeImeService.kt`：spacer 格子视图补右侧键距（`marginEnd = ime_key_spacing`）——列间隔由「前键 marginEnd 12 + spacer 42 = 54px」修正为「12 + 42 + 12 = 66px」，与画板① `.krow{gap:12px}` 对 spacer 两侧均生效的口径一致；一处改动，四列自然回位。
- `dimens.xml`：`ime_column_spacer`（21dp=42px 本体）值不变，注释写明画板① flex gap 双侧口径与 66px 实宽合成方式，防再犯。
- `KeyboardLayoutTest.kt`：新增 `columnRhythmMatchesArtboard`（纯 Kotlin 口径计算器锁定画板①列原点）——字母列 330 / 功能列 1028 / 图标列 1120（相对键区；屏坐标 +108 = 438/1136/1228）、spacer 步进 66px、行 3/4 功能列同原点、完成键 1120 与图标列左缘对齐、空格→完成 12px 键距。

## 原因

T5 归档后户主走查发现完成键与上方图标列错位 24px、空格→完成间距 36px（设计稿 12px）。像素核查根因：实现把画板① flex gap 只计单侧（`ime_column_spacer` 21dp=42px，其后仅跟一道 12px 键距），每过一道 spacer 后续列左移 12px——字母列 −12、功能列与图标列 −24；完成键按画板①绝对坐标定位未动，故相对错位。证据：`.shots-t5/audit_done_alignment.png`。

## 踩过的坑

1. 画板① flex gap 双侧口径坑（T5 坑 1 同类）：CSS flex 的 `gap` 对 spacer 元素两侧各生效一次，列间隔 = 12+42+12 = 66px，不是「spacer 42 + 一侧 12 = 54px」。实现用 margin 模拟 gap 时只在前键一侧加了间距，spacer 后侧漏了 12px——每过一道 spacer，后续所有列累计左移 12px。已把双侧口径写进 `ime_column_spacer` Token 注释与列节奏单测（`columnRhythmMatchesArtboard`），防后续键盘（T8 符号键盘）复用 Cell 结构时再犯。
2. 像素核查扫描窗口要避开相邻元素：首扫「图标列左缘」起点落在功能列键帽内、扫「行 2 顶缘」起点落在行 1 键帽底缘内，各自得出 −48px / −14px 的假偏差；修正扫描窗口（从相邻元素边界之外起扫）后全部精确命中。测几何先算相邻元素占位区间，扫描窗口取区间外。
3. 行 4 键帽顶缘 +2px 偏移根因待查（T8 前置注意项）：T28 修复后行 4 键帽顶缘 894（布局目标 892、T5 归档版实测 892），键帽高 92→90、底缘不变——与 spacer `marginEnd` 强相关，机制未明（LinearLayout 固定高容器内子 View 顶 +2 / 高 −2 / 底不变）。量级容差内、不可感知，不影响本 bugfix 判定；**T8 重构键盘布局前必须先查明该机制**，不查明有累积风险。
