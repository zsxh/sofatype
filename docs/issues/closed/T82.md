## 目标

从 SofaType 设置页返回/退出后，系统默认输入法保持本 IME，不再被自动夺回搜狗；若平台夺回链无法在应用侧根除，至少提供用户可感知、可一键恢复的通道。产出含两段：真机诊断取证（补齐坑 5 挂账的指纹核验）+ 依诊断拍板的修复实施。

## 改动（计划，开工后按实际更新；修复方向需户主拍板）

- **①诊断先行（真机 MiTV4；已完成 2026-11-18 真机批次，取证留档）**：复现「设置页 BACK 二次退出 → 夺回」链，全窗 logcat 抓 `Force stopping com.sofatype.ime` 指纹与杀进程发起方、退出前后 `default_input_method` 与 IME 进程 pid 双读——补齐 2026-11-13 T54/T62 批次挂账的指纹核验，定性「退出沿 IME 进程死亡」的直接触发。诊断范围：BACK 二次退出主路径 ≥3 轮 + HOME 退出 / 设置子页返回变体各 ≥1 轮 + 键盘窗口显示态对比 1 轮。
  **诊断结论（2026-11-18，review-qa 真机批次；全文与 53 件证据见 `screenshots/T82/t82m-diagnosis-report.md`）**：
  - 规定轮次全数执行：主路径 3 轮 + HOME 变体 1 轮 + 子页返回变体 1 轮 + 键盘收起态退出对比 1 轮，5/5 退出沿全抓到 `Force stopping com.sofatype.ime` 指纹（`logcat -G 4M` 扩容防 chatty 吞没后零漏抓，2026-11-12 无指纹实例与 256K 小缓冲吞没假设相容）。
  - 发起方 = system_server（pid 2988），非 TvMgr 类第三方清理者；杀因标记 = `MitvWindowManager: com.sofatype.ime has system window,so kill it`（与坑 9 屏保链同族指纹）；杀包 → IMMS 解绑 + force-stop 重置 + 重选系统默认搜狗（约 +650ms）。
  - 定性 = **IME 系统窗口链，非设置页前台进程清理连带**：HOME 变体中设置 Activity 仅 pause 未 finish 仍 20ms 内被杀（「Activity finish/destroy 连带」假设被反证排除）；键盘收起后 IME 窗口对象仍挂包名下，前台切走沿平台对该包 force-stop；对照轮从未 show 过窗口的 IME 进程经历页面往返零杀动作——窗口创建过即成风险态。
  - 对方案 A 的含义（事实陈述，供拍板）：主候选 A 的机制前提是「平台清杀前台设置页所在进程连带 IME」，本轮定性显示杀的是持系统窗口的 IME 包本身、与前台 Activity 所在进程无关，A 的前提与诊断结论不符；兜底 B2 引导选回通道不受该结论影响。
  - **补充轮 · 第三方宿主验证（2026-11-18 09:59–10:12，户主补充指令显式批准）**：目标验证「第三方应用弹键盘后切走是否同样触发」。桌面「BiliBili」图标实际为 `com.chinasoul.bt/.LauncherPink`（户主所指 bilibili/bt 应用）；其搜索页双击 tap 输入框弹出 sofatype 键盘（显示态截图 + `mInputShown=true` 双证）后切走：主路径 HOME 2/2 + BACK 变体 1 轮（该应用主入口拦截 BACK、退出沿不可达，如实记录）**全程零指纹、零杀、零夺回**（pid 10104 存活 ps+dumpsys 双证），与设置页 5/5 全触发形成干净对照。**触发形态集合修正**：已知触发 = ①sofatype 自家 Activity 前台切走沿（对照事实表述：平台「has system window」检查命中刚被切走的前台包，自家包持 IME 窗口命中即杀、第三方包无系统窗口不杀）②空闲期屏保沿；第三方宿主切走沿实证不在集合内。
