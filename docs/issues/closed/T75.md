## 目标

修复真实用户路径「TV 退出远程输入再重开 + 同一手机重扫码」在决策 61 保号窗口（15 分钟）内仍换号的体验缺陷。

根因 = 服务每轮随机端口（决策 16）+ H5 `deviceKey` 存 localStorage 按 origin（协议+IP+端口）隔离 → 端口一变，同一手机即被判新设备（T72 坑 2、DEV-GUIDE 备选通道坑 6；户主 2026-11-15 真实使用复现，预期保号 01 实得 02）。

交付：端口「首次随机、持久化、使用期复用」——TV 端服务 URL origin 跨退出重开稳定，决策 61 保号链在真实路径生效。

## 改动

<!-- 2026-11-15 Round 1 按实际实现更新的事实清单 -->

- 新增 `app/src/main/java/com/sofatype/ime/remote/RemotePortPolicy.kt`：端口分配策略（纯 Kotlin，无 android 依赖）——动态段常量 49152–65535、随机重试上限常量 3；`resolve(bind)` 流程 = 复用持久化端口 → 被占换动态段随机（上限 3 次）→ 随机绑定成功持久化；非占用失败原样终止不重试；越界 / 非法持久化值按无记录处理。同文件含持久化接口 `RemotePortPersistence`（仅端口号读写）与结论模型 `PortBindAttempt` / `PortAssignment`。
- `RemoteInputServer.kt`：`start()` 绑定前一律 `setReuseAddress(true)`；绑定失败按 `BindException` 分类，`StartResult.Failed` 增 `portInUse` 字段（默认 false）。
- `RemoteInputServerManager.kt`：`startInternal` 端口来源改经 `RemotePortPolicy` 解析（原内联 requestedPort=0 随机退役）；服务实例构造抽为 `buildRemoteInputServer` 工厂（每个候选端口独立实例，仅绑定成功实例进入运行态）；新增 SharedPreferences 适配 `RemoteServicePortStore`（prefs 文件 `remote_service_prefs`，键 `service_port`）；新增启动日志行：复用命中 / 换新随机 / 首次随机 / 分配失败（TAG=RemoteInputServer，原有地址行不变）。
- 测试：新增 `app/src/test/java/com/sofatype/ime/remote/RemotePortPolicyTest.kt`（11 用例：复用命中 / 持久化回读 / 被占换新 / 重试上限 / 非占用失败即停 / 越界值 / 动态段边界）；`RemoteInputServerLifecycleTest.kt` 增 2 用例（被占绑定带 portInUse 标记 / 连接拆除后同端口立即重绑成功）。
- 协议与 H5 资产零改动；无第三方依赖新增；持久化只写端口号一个配置项。

## 原因

户主 2026-11-15 真实使用撞上「退出重开 + 重扫码」15 分钟内换号。固定全局端口的候选方案经户主拍板调整为「随机找到可用的端口，在使用期间尽量复用它」（决策 63）：每台 TV 各自持有稳定端口，保留随机分配的防冲突优点，无全局固定值单点。
