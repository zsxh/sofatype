## 目标

手机上长按远程输入页编辑卡出现系统「粘贴 / 全选 / 选择」菜单，粘贴内容进入草稿并按既有口径推送 TV（FR-C4）。附带恢复同架构牺牲的原生编辑能力：长按选字 / 拖动选择、光标点选定位到文字中间。

## 改动

- `app/src/main/assets/remote/index.html` 单文件改动：
  - `.ghost-input`（textarea）可见化，作为唯一编辑面：去掉 `opacity: 0 / color: transparent / caret-color: transparent`；按 PRD 6.3 复刻视觉（22px / 34px 行高、`--text-primary` 文字色、`caret-color: var(--accent)`、卡内 padding 20px、`font-family: inherit` 显式继承）。
  - 原自绘显示层（`.editor-content` + `#content-text` + `.cursor`）降级为隐藏镜像（`visibility: hidden` 保持排版），新增用途：测量文字末尾坐标，定位未聚焦态假光标 `.fake-cursor`（聚焦后隐藏，原生插入符接管；FR-C3「末尾光标」口径不破）。
  - 字数计数器加 `pointer-events: none`（计数浮层不挡 textarea 点击 / 长按）。
  - JS 同步调整：新增 `positionCursor()`（镜像滚动随输入层同步 + 假光标定位 + 焦点态切换）；`render()` 改为「值相等不赋值」保留原生光标位（中途插入 / 选区不被重置）；删除按钮改值后手动滚动跟随末尾；`input` 事件钳制与推送逻辑、删除 / 清空 / 上屏 / committed 清空口径不变（FR-C4/C7）。
- TV 端零改动；WS 协议零改动；既有单测断言面（aria-label、色值 Token）不受影响。

## 原因

2026-11-14 户主报告：手机上长按输入框不出现「粘贴」选项。根因：页面采用「透明输入层」架构——真正接收输入的 textarea 被 `opacity: 0 / color: transparent` 隐藏，可见文字由上层 div 自绘回显；手机浏览器的粘贴 / 选择菜单只对可见的可编辑文本出现，故菜单不出（或以不可见形态出现）。已排除 `contextmenu` 拦截与 `user-select: none`（页面均未使用）。方案评估：clipboard API 方案不可行（TV 局域网 HTTP 非 HTTPS 安全上下文，无读权限）；仅调透明度的轻量方案各内核行为不可靠；户主 2026-11-14 拍板方案 A（textarea 可见化）开工。

## 踩过的坑

- 无头浏览器 CDP 通道取证不到系统长按菜单：菜单为浏览器 / 系统层 UI，不入页面 DOM 与截图——粘贴菜单本体只能真机验收，模拟通道只能验证「长按落点 = 可编辑元素 + 文字可见」的结构前提。
- 本地静态服务（无 WS）打开页面时 WS 连接失败属预期路径，状态行「连接失败…重新扫码」即其表现；编辑面行为不受影响，可独立走查（推送函数静默跳过，不抛错）。
