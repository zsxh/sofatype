## 目标

手机可安全配对到 TV：扫码带一次性 token，握手成功显示「已连接 · TV名」。token 用后失效，无 token 被拒。

## 改动

一次性 token 生成与校验；ZXing core 生成二维码；配对卡仅二维码 + URL 一行（决策 4）；hello / state 握手下发 TV 名与字数上限；token 配对后失效。

实际执行内容（2026-11-07 实现）：

- 新增 `app/src/main/java/com/sofatype/ime/remote/PairingTokenStore.kt`：一次性 token（FR-B10）。
  SecureRandom 16 字节 → Base64URL 22 字符（复用 T13 Base64Codec 换 URL 安全字母表）；
  `issue` 签发即替换旧值、`consume` 校验并一次性置空、猜错不吊销正确 token、`clear` 随服务停止清空；仅驻内存。
- 新增 `remote/MinimalJson.kt`：跨屏协议最小 JSON（纯 Kotlin，无第三方库）。解析顶层对象标量字段
  （字符串解转义含 `\uXXXX`、数字/true/false/null 原文）、序列化转义；嵌套结构解析失败按拒绝处理。
- 新增 `remote/PairingSession.kt`：hello/state 握手（PRD 第 7 章）。hello { token, deviceName } →
  有效 token 回 state { connected:true, tvName, charLimit:200 } 且 token 立即失效、连接保持（T15 业务前置）；
  缺失/无效/已使用回 state { connected:false } 后以 4001 关闭（RFC 6455 应用段码）；
  非 hello 消息忽略连接保持（T15 接入）；deviceName 接收即弃，不存储不记日志（隐私红线）。
- 新增 `remote/QrCodeEncoder.kt`：ZXing core `QRCodeWriter` 编码配对 URL 为 BitMatrix
  （纠错 M、UTF-8、规范默认 4 模块静区）；解码回环由单测覆盖。
- `RemoteInputServer.kt`：新增 `/ws` 会话委托接口 `WsSessionDelegate` 与应答动作 `WsReply`
  （None / Text / TextThenClose）；无委托保持 T13 回环口径（既有回环单测基线不变）；
  TextThenClose 路径发 CLOSE 后按 RFC 6455 §7.1.1 等待对端 CLOSE（≤1s 非阻塞轮询）再断 TCP。
- `RemoteInputServerManager.kt`：启动时签发 token、装配 PairingSession（tvName = `Build.MODEL`，空值兜底
  「Android TV」；charLimit = 200 对齐 FR-C7）；新增 `pairingUrl()`（二维码与副卡地址行同源，含 token）、
  `isPairingTokenActive()`、`onPairingStateChanged` 回调（UI 刷新；T17 状态机重构前过渡）；停止清空 token。
- `PlaceholderPage`（HttpExchange.kt）：占位页改为配对验证页——URL query 取 token → WS /ws →
  hello { token, deviceName:"browser" } → state 后显示「已连接 · TV名」与「字数上限 200 字」；
  被拒显示「配对失败：token 无效或已使用，请重新扫码」；连接关闭显示关闭码；纯原生 HTML/CSS/JS（决策 20）。
- 新增 `app/src/main/java/com/sofatype/ime/PairingCard.kt`：配对卡装配（FR-B4）——副卡整卡 =
  二维码（376×376 px = 188dp，圆角 38px 复用 `ime_card_corner` Token，轮廓裁剪）+ 下方地址一行
  （accent_text = PRD 6.1 URL 色，字 22px Token，letter-spacing 0.023em 对齐画板⑤ 0.5px@22px），
  二维码下方无其他文案（决策 4）；地址行基准字号放不下时按 1px 步进缩小（下限 6sp）守「一行 + 地址一致」；
  黑模块白底为扫码对比度所需（画板⑤ 二维码资产同形，不入主题配色方案）；二维码 contentDescription =
  「跨屏输入配对二维码」（画板⑤ alt 原文）；纯展示无焦点。
- `SofatypeImeService.kt`：绑定 `side_card`；服务运行中渲染配对卡（onCreateInputView 补渲染 +
  Manager 状态回调刷新）；`onDestroy` 解除回调；停止后副卡清空回占位。
- `res/values/dimens.xml`：新增配对卡 Token 4 项（`ime_qr_size` 188dp / `ime_pairing_padding` 20dp /
  `ime_pairing_gap` 5dp / `ime_pairing_url_text` 11sp，画板⑤ 1080p ÷2 口径）。
- `RemoteServerDebugReceiver.kt`（debug）：STATUS 动作增加配对地址与 token 状态输出（仅 debug 构建）。

  纯 Java 库无嵌入件）；release 打包链路随标准模板构建验证无异常。
- 单元测试：新增 5 文件 37 用例——PairingTokenStoreTest（7：签发格式/一次性消费/猜错不吊销/重签发作废/清空）、

## 原因
FR-B4/B10；局域网明文通道的安全底线是 O-8 首版口径：一次性 token + 会话结束清缓冲。

## 踩过的坑

1. Kotlin 无 `\f` 转义：JSON 转义处理的换页符须写 `'\u000C'`，写裸控制字符不可靠。
2. 本机无头浏览器截图通道在走查后段失效：首个 CLI 截图实例挂死后，后续 CLI 与 CDP 捕获一律
   「Unable to capture screenshot」/「CVDisplayLinkCreateWithCGDisplay failed」，清尽进程无效——
   判定为本会话窗口服务状态问题（非服务端问题：同期 python3 WS 客户端、curl、模拟器服务全部正常）。
   已采取的证据替代：valid 页截图（失效前产出）+ 协议级回执（python3 WS 客户端）+ logcat 事件 + JVM 单测。
3. AVD 快照损坏致冷启 offline：多轮 WS 走查后模拟器强停，`snapshots/default_boot` 记录了劣化的
   slirp 套接字状态（日志「Failed to load slirp-socket」），之后每次启动卡 `offline`；
   删除该快照目录（保留 userdata）后 20 秒恢复 `device`。已记 `local/DEV-GUIDE.md`。
4. 服务端发 CLOSE 帧后立即断 TCP 会让浏览器端关闭握手被截断（被拒页 loading 态不结束）；
   已按 RFC 6455 §7.1.1 在 TextThenClose 路径增加 ≤1s 对端 CLOSE 等待（`awaitPeerClose`，
   非阻塞轮询，不设全局 soTimeout 以免空闲会话被读超时误断），python3 客户端验证回执后干净 EOF。
