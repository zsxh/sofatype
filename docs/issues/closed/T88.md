## 目标

修订 T59 口径 3 的隐藏态确认键语义，按户主 2026-11-19 拍板方向：

1. **焦点在输入框（输入会话活跃）**：按 OK/回车/小键盘回车 → 消费 + 唤起键盘（T86 分层兜底保留服役，抗真机 `IllegalAccessError`）。
2. **其余任何情况（会话已结束 / 无会话）**：确认键与 IME 无关——不消费、不唤起，透传宿主（`return super`）。

消除第三方宿主场景「按 OK 被 IME 劫持弹键盘」（焦点已移出输入框 / 应用已切走的确认键，现状仍被无条件消费）；同时保留「焦点在输入框按 OK 唤起」路径。

## 背景（户主反馈与根因链，2026-11-19）

- T86 真机批次（当日）验证通过后，户主实际使用反馈：「真机上的 OK 键怎么被篡改成弹出键盘了?!」——收起键盘后按 OK 本意操作宿主（选词条 / 点按钮 / 确认对话框），结果一律弹键盘。
- 根因链：①MiTV4 固件形态 = 键盘隐藏后按键仍路由进 IME 会话（T53 trace 实证）；②T59 口径 3（2026-11-11 户主拍板 7 条之一）让确认键隐藏态**无条件**消费 + 唤起，且该分支无会话状态判定——连会话已结束（解绑态）仍被固件派发进 IME 的确认键也被消费（BACK / 方向键有解绑态透传判定，确认键没有）；③T59 拍板时的验证全在自家宿主（pre-IME 分路先拦，键到不了 IME 该分支），第三方宿主场景是拍板盲区（T59 缺口清单当时已标注「requestShowSelf 分支需第三方宿主场景实测」未执行）；④T59 口径在真机从未成功过（`requestShowSelf` 必崩，T85 取证 10 条 FATAL 全为第三方宿主真实使用），T86 决策 68 使其首次生效，户主首次真实体验即暴露语义缺陷。

- `app/src/main/java/com/sofatype/ime/SofatypeImeService.kt` 确认键隐藏态分支：
  - 输入会话活跃（`getCurrentInputStarted()` 等框架信号，判定 = 焦点在可输入控件）→ 保留现状：`swallowed（输入窗隐藏态）` trace + `HiddenConfirmWake` 分层兜底唤起（T86 决策 67 结构不变）；
