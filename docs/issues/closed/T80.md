## 目标

中文组合态下按数字（屏幕数字键 OK / 遥控器数字键码两条通道）不再吞拼音、不再状态失同步：组合串先原样上屏，数字紧随其后直出（如组合 "ni" 按 5 → 正文 "ni5"）；composer / 输入框组合区 / 光标三者保持同步，删除链路在混输全程语义正确（组合串先删、删空接删正文，无「越删越多」、无「删除无反应」）。

## 改动

实际实现（dev Round 1，2026-11-16）：

1. `SofatypeImeService` 的 `execute()` `KeyAction.Text` 直出分支：字母键盘 × 中文模式 × 非字母直出键（数字列 / `.com` / `@`）在 `commitText` 前先 `finishComposition()`（组合串原样上屏 + composer 复位）+ `refreshCandidatesBar()`（候选栏同步清空），数字紧随其后直出。判定带 `LanguageMode.CHINESE` × 组合非空双门控——英文模式 / 符号键盘 / 无组合态不进该分支（空组合终结为无操作，行为不变）。网格 OK 与拦截后的键码两通道同走 execute，修一处两通道同治。
2. `KeyboardLayout.digitIdForKeyCode(keyCode)`：KEYCODE_0(7)..KEYCODE_9(16) → `digit_0`..`digit_9` 全表映射（模型层，纯 Kotlin 无 Android 依赖，与 `letterIdForKeyCode` 同族；KEYCODE_SPACE 等非数字键码返回 null，R-2 空格键面不动）。
3. `onKeyDown` 数字键码拦截：KEYCODE_0-9 在 T45 字母拦截同一守卫块（ACTION_DOWN 首按 × 字母键盘 × 中文模式 × 非远程 × 显示态）映射对应数字键走 `execute()`；`onKeyUp` 数字键码 UP 独立分支（与字母 UP 同款条件）显示态一律消费、隐藏态透传（T59 对称口径）。
4. 单测 `T80DigitMixedInputTest`（9 例）：数字键码映射全表 / 边界 null / 与字母映射互斥 / 映射 id 全命中数字键模型且输出值一致；组合态数字直出前序语义模型侧锁定（committedText 原样上屏 + reset 复位）；服务层源码扫描守卫（直出分支终结序位 / 拦截守卫与 T45 同构 / UP 消费口径 / T48 DEL 与空格键码零回归）。

未动（红线确认）：DEL 拦截分支（T48）、空格键码与空格键面语义（R-2 另行评估）、远程模式 / 隐藏态守卫口径、`onEvaluateFullscreenMode`、焦点策略（决策 64）；零新依赖，不改 designs/ 与 PRD。

## 原因

2026-11-16 户主反馈「中文和数字混输和删除等操作有逻辑问题」。lead 模拟器（API 34）走查实锤 4 项失同步（证据 `screenshots/数字混输/` + `ImeKeyTrace-full.log`）：

1. **网格数字键吞拼音**：组合 "ni" 按数字键 OK → 正文变 "5"，拼音被替换丢失；候选栏残留旧候选（`commitText` 替换组合区、composer 不复位）。
2. **失同步连锁**：其后打字母旧拼音复活（"5" → "5nip"）；按删除反而长字母（"0645" → "0645n"）；composer 残 1 字符时 DEL 被幻影组合串吃掉、正文不动。
3. **遥控数字键码未拦截**：落框架直写，插在组合区之后；composer 失同步致顺序错乱（按键 n,i,5,e → 正文 "nie5"）。
4. **光标锚死**：组合清空 / 选词后光标锚在残留数字之前——后续输入全插它前面（"你5" → "你20245"）、退格删不到它（两发 KEYCODE_DEL 到达 IME、正文零变化）；方向键移一格后删除立即恢复。

对照组正常（无组合态数字直出 / 已上屏混输文本逐字删除 / 组合串删除不伤正文 / 长按连删），问题全部集中在「组合态 × 数字」交叉点。PRD FR-A9 只定义无组合态数字直出（T10 验收同口径），「组合态 × 数字」此前无拍板口径；T45 / T48 已拦字母与 DEL 键码，数字为漏网第三类。
