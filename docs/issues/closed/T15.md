## 踩过的坑

1. **debug 广播显式组件的包段写错 → 广播静默不派发**：组件写成了 `com.sofatype.ime.debug/...`（把源集路径当包名），实际 applicationId 是 `com.sofatype.ime`；`am broadcast` 对不存在组件返回 `result=0` 无任何报错，AMS 记录 `disp=1970`（从未派发），极易误判为 stopped 态 / 系统策略 / 快照劣化。正确写法 `-n com.sofatype.ime/.remote.RemoteServerDebugReceiver`（对照 T14 时代 dumpsys 成功记录核实）。正确组件下 T13 坑 11 的「先 am start 再显式广播」依然必要。
2. **H5 满卡 200 字溢出**：设计稿画板只有 7 字状态；200 字 × 22px 行高 34px ≈ 374px > 编辑卡内容区 296px，实测文字溢出卡外盖住按钮与页脚。修复：`.editor-content` 卡内滚动（`max-height:100%` + `overflow-y:auto`）+ 渲染后滚动跟随末尾；hint / 计数 `z-index` 置顶。轻提示初版用 `accent-wash` 半透明底被大字压过，改 `key` 底 + `border-accent` 描边后清晰可读。
3. **浏览器报错页 tab 自动重载抢先消费 token**：页面 URL 在 redir 未就绪时打开（连接失败报错页）；`adb emu redir add` 生效后 Chrome 自动重载该 tab → hello 抢先配对，后续新 tab 被拒。规避：换新 token 前 `/json/close` 清掉全部残留 page tab，再开新 tab；驱动脚本对「未连接」直接中止（防错误页上空跑）。
4. **`adb emu redir` 端口随服务重启变化**：端口随机（决策 16），每轮 STOP→START 后新端口都要 `redir add`；漏加时 Mac 侧 curl 不可达，页面打开失败（表现同 token 被拒，注意区分：可达性先用 curl 核实）。
5. **H5 页字节缓存与服务会话绑定**：Manager 内缓存若跨启停存活，资产更新后旧页不生效；已改为每次服务启动失效缓存（服务运行期内仍缓存，避免每次请求读 assets）。
6. **inline span 无 `scrollTop`**：满卡滚动跟随首版把 `scrollTop` 设在文本 span 上，赋值静默无效（DOM 层 inline 元素无滚动盒），截图肉眼可见「停开头」但当时未察觉；滚动容器必须是有 `overflow` 的块级盒。Round 1 评审实测揪出，一行修复。
7. **冷启后立即 tap 唤不起键盘**：`ime set` 后马上 `input tap` 输入框，IME 视图未就绪，键盘不弹出（`mInputShown=false`）——TV 端截图扑空（无键盘视图即无远程显示区）；tap 后核对 `dumpsys input_method` 的 `mInputShown` 再取证。补渲染路径（缓冲非空时唤起键盘即恢复大字）反向成了「键盘重建不丢显示」的验证样例。
