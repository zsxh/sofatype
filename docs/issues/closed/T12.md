## 搜狗对照定性（2026-11-08）

## 踩过的坑

1. **收起后发 CENTER 唤起键盘，CENTER 直落 IME 初始焦点键（digit_1）直出字符**：键盘收起后宿主 `showSoftInput` 重弹与注入存在竞争，注入的 CENTER 在重弹完成后到达 IME，落在初始焦点键 digit_1 上直出「1」（3 次复现：09:55:50 / 09:56:35 / 09:57:20，trace `onKeyDown keyCode=23 focus=digit_1`）。HANDOFF 坑清单「CENTER 收起延迟 120ms 防宿主覆盖——时序常量真机待复核」的真机实锤：真机竞争窗口大于 120ms。处置：唤起后先核对焦点 trace 再注入；该竞争使「CENTER 唤起」路径在真机不可靠（内容被意外插入 3 个「1」，已在走查中如实记录）。防覆盖加固是否调整时序常量，报 lead 由户主决定（本轮未改代码）。
2. **杀 IME 进程（前台同进程 Activity 场景）→ 默认输入法被系统回退为搜狗**：坑 3 的扩展形态。前台 Activity 与 IME 同进程（com.sofatype.ime 内 SettingsActivity 与 SofatypeImeService 同 pid），`run-as kill` 后同进程前台 Activity 死亡，系统回退 `default_input_method` 为搜狗（2/2 复现）且前台任务回退到下层 app；前台为第三方 app 时纯杀 IME 进程不夺回（变量隔离轮实证）。属 Android 6 平台回退行为与「宿主与 IME 同进程」架构叠加，非功能代码缺陷；「防夺回」加固（独立进程宿主或回退后自动恢复）需户主拍板另立任务（本轮未改代码）。
3. **候选首行装载量漂移（观察项，非阻塞）**：同一组合串「e」的候选栏首行 chips 数在「9 + 更多⌄」与「10 + 更多⌄」间波动（10:05 / 10:06:30 / 10:10 三轮实测，截图 `t12-e-recheck.png` / `t12-t11-toggle2.png` / `t12-t11-fit-count.png`）。机制疑为 `bindCandidates` 以候选栏上一次布局遗留宽（`bar.width`）作可用宽度的状态依赖：上一轮行内容不同 → 本轮 available 微变 → `fitCount` 在 9/10 间漂移。用户可感知表现为「焦点右移到『更多⌄』所需 RIGHT 次数不稳定」。候选内容与选择正确性不受影响；是否修复报 lead 转户主决定（本轮未改代码）。
4. **`uiautomator dump`（Android 6）退出阶段产生 FATAL EXCEPTION**：为 dump 工具进程自身（shell uid）的 SecurityException（`unregisterUiTestAutomationService` 权限拒绝），非应用崩溃。真机 logcat 全程核查 FATAL 时须按 pid/uid 排除该噪音。
5. **注入丢事件真机同坑**：RIGHT 长链偶发单键丢失（ImeKeyTrace 无对应记录即丢失，10:07:14 一轮实证），按 HANDOFF 口径重发该键并如实记录次数；候选行内长 RIGHT 链建议逐键发 + trace 核对。
