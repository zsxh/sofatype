## 目标

多输入框场景只扫一次码：手机点「上屏」写入成功后，WS 连接与远程模式保持，手机端草稿清空并提示「已上屏」后可直接继续编辑、再次上屏；上屏内容始终落电视当前焦点输入框。防会话窗口无限延长：连接保持期间无任何 WS 消息收发满 10 分钟自动停服退出并收起键盘（走 FR-B7 通知链路通知手机）。安全与隐私边界不破：token 一次性、断连/退出即清缓冲、输入内容不持久化不上云、协议无新增消息类型。

## 改动

- `app/src/main/java/com/sofatype/ime/remote/RemoteInputServerManager.kt`
  - `onRemoteCommit`：写入成功不再 `stop()`——处置收口新增模型 `RemoteCommitAftermath`（单一事实源）：主线程执行 IME 写入后，teardown 线程先回执 `committed { ok }`；成功分支清空远程缓冲并经主线程通知 UI（大字区清空，远程模式与连接保持、状态行保持「已连接」）；失败分支缓冲与远程模式保持（手机端提示失败可重试）。停服仅由显式退出 / 空闲到期 / 网络重建触发。
  - 新增「已连接无活动」空闲跟踪：判定收口新增模型 `RemoteConnectedIdlePolicy`（正式阈值 10 分钟）；活动口径 = 已配对会话上的协议消息收发（`onPaired` / `onRemoteInput` / `onRemoteClear` / `onRemoteCommit` 登记活动）；排程沿用主线程 post 串行化 + 任务身份比对（T22/T25 模式），到期以运行态 + 已配对会话复核竞态后走既有 `stop()` 完整清理链路（先回发 `disconnect { reason:"tv-exit" }` 再按 1000 关连接后停服）+ `onRemoteIdleExpired` 收起键盘。与既有「无手机连接」30 分钟空闲（T25）并存互不干扰（有连接看本跟踪、无连接看 T25；断连 / 停服两侧一并解除）。验证通道新增 debug 入口 `debugConnectedIdleExpire()`（决策 21 debug 门控：活动回拨一个完整窗口后立即到期，走与真实到期完全相同的判定与清理路径，正式阈值不改动）。

## 原因

户主反馈：TV 宿主应用存在多个输入框时，现行 FR-B6「上屏成功即停服收起」使每次上屏拆一次会话，下个输入框须重新进远程模式并重新扫码（新端口 + 新一次性 token，旧地址必死），效率过低。2026-11-14 户主拍板方案 A（上屏保活连续输入）立项。

## 踩过的坑

- **模拟器「无焦点输入框」失败注入两通道不可行（2026-11-14 走查实测）**：HOME 键与切无输入框前台（设置页）都不会使 IME 侧 `currentInputConnection` 置空——宿主切走后旧 IC 变为「陈旧句柄」，`commitText` 不抛错（代码判 true、回执 ok:true）但写入被平台丢弃（宿主正文无该内容）。真实失败路径（`?: false`「键盘侧未就绪」分支）须受控 `ime set` 切走本 IME（服务 onDestroy 清回调）才触发；重试腿须等切回后键盘实际显示（`onCreateInputView` 重新注册回调，`dumpsys input_method` mInputShown=true）再 commit。真机复验失败注入建议沿用此通道。陈旧 IC 写入丢失属宿主侧平台行为，非 T70 引入（T62 黑洞家族近邻），不修。
- **模拟器截屏耗时漂移**：走查编排里 `adb shell screencap` 单次往返可拖到数秒（冷连接），定时截屏的落点比 sleep 预算晚——多帧证据须按内容判读（本轮 c2/c3 实际落点晚于预算约 4~6s），勿按时间戳倒推帧序。
