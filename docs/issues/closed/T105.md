## 背景

2026-11-24 户主会话拍板（真机故障调查立项，修复方向三选一后定「建正式发布章，一次性迁移」）。

根因：T100 发布链按「unsigned 直发」口径把 `sofatype-<版本>-unsigned.apk` 直发 GitHub Releases；T103/T104 应用内更新的下载地址构造恰好指向该 unsigned 资产。Android 任何版本拒绝安装无签名 APK——2026-11-24 22:19 MiTV4 真机实测：应用内检查更新发现 v0.2.2 → 经 gh-proxy.com 下载完成 3 108 959 字节（与资产字节、sha256 一致，代理链无损）→ 系统安装器确认安装后 `PackageManager: Failed to collect certificates` + `error_code=-103`（`INSTALL_PARSE_FAILED_NO_CERTIFICATES`）→ 返回设置页判 NOT_UPDATED「安装失败」。**按现状发布，任何设备上应用内更新必失败**；检查、下载、代理回退、UI 通道机制各段证据均正常（安装器可读 cacheDir 文件、确认框与版本判定链工作正确）。

历史装机未暴露此问题：装机一直走本地 jarsigner 重签 + `pm install` 路径（签名在发布链之外）。

## 需求与口径

1. **建正式发布专用 keystore（「发布章」）**：本地生成、gitignore 范围内保管（不入库，存放位置与密码不入 git 文档）；RSA ≥2048、有效期 ≥25 年；别名与密码实施时定（强随机）。修订 T100 口径「unsigned 直发」为「签名直发」。
2. **CI 签名**：`release.yml` 增加签名步骤，keystore 经 GitHub Secrets 注入（base64 + store/key 密码 + 别名）；**Secrets 缺失时发布必须失败**（防 unsigned 再直发）；发布资产命名改 `sofatype-<版本>.apk`（去 `-unsigned`）。
3. **应用侧下载地址构造同步**：`UpdateAtomParser.downloadUrl` 产物名去 `-unsigned`，单测随口径更新；检查链（Atom / 代理回退 / 超时 / UI 呈现）口径不变。
4. **版本递增 0.2.3(5)**（决策 19 随发布批次递增），CHANGELOG 出节，push tag `v0.2.3` 触发直发签名资产。
5. **真机一次性迁章**：卸载现装 debug 章 0.2.1(3) → 安装 0.2.3(5)（发布章，预期 `pkgFlags` 无 `DEBUGGABLE`）→ 按 DEV-GUIDE 1.5 与设备档案口径恢复 `default_input_method` / `enabled_input_methods` 并核对装机态；此后装机证书 = 发布章，应用内更新链章一致可用。
6. **红线自查**：keystore 与密码不入 git、不出现在 Actions 日志；入库文档不引用不入库文件路径（指针规则见 AGENTS.md）。

## 方案评估（预评）

- 影响面：`.github/workflows/release.yml`（签名步骤 + 产物命名 + Secrets 缺失门禁）；`UpdateAtomParser.kt` + 单测（URL 构造）；`app/build.gradle.kts`（版本号）；`CHANGELOG.md`；真机装机操作一轮。运行时除下载 URL 外零行为变化。
- 签名实现二选一：①gradle `signingConfig` 经环境变量注入（CI 专用，本机不配 env 时维持现状产物；AGP 同出 v1+v2，API 23 只验 v1 兼容，对齐由 AGP 负责，单源最简）；②构建后 `apksigner` 后处理（DEV-GUIDE 2.4 模拟器口径同款）。实施时定，倾向①；核对注入 signingConfig 后的产物名并同步 release.yml 复制步骤。
- 回归面：更新检查三态与失败 Toast、代理顺序回退链、下载进度、SESSION 通道（API 24+）、UI 通道版本判定链均不动；真机升级沿预期副作用（default 夺回 + 设置页任务被杀 + 安装许可弹窗代点）按设备档案四.1/四.3 应对。
- 风险与取舍：GitHub 公开仓库 Actions Secrets 不进日志、不进产物，泄漏面可接受；旧 release 的 unsigned 资产留存不污染新链（下载地址恒指最新 tag 的资产名）；`Failed to collect manifest digest` 是 MiTV 安装器确认框阶段对 unsigned 包的无害告警形态，签名后预期消失，若仍出现且不阻塞安装则不处理（留证即可）。
- 验收窗口限制：应用内更新「正向全链」（发现新版→下载→安装成功→版本变化）需要存在比装机更新的版本。0.2.3(5) 迁移装机后先真源验 UP_TO_DATE；正向全链走 debug 注入通道指 mock 资产验（release 包注入通道可用性实施时核实），并在下一次真实发版时真源复验一次。

### 实施回填（2026-11-24）

- 发布专用 keystore（PKCS12 / RSA 2048 / 25 年 / 别名 `sofatype-release`，SHA256 指纹 `9F:AC:22:46:…:F5:CD:DA`）本地保管不入库；密码与 Secrets 映射同步本地留档（git 外）
- `.github/workflows/release.yml`：还原 keystore 步骤（四 Secrets 缺一即失败）→ `GITHUB_ENV` 注入四变量 → 产物复制 `sofatype-<版本>.apk`（缺签名产物即失败）→ files 口径 `sofatype-*.apk`
- `app/build.gradle.kts`：`ciRelease` signingConfig 环境变量注入（四变量同进同出，部分缺失抛 GradleException）；版本递增 0.2.3(5)
- `UpdateAtomParser.kt`：下载地址去 `-unsigned`（KDoc 失实口径同步清理）
- `UpdateAtomParserTest.kt` / `UpdateCheckTest.kt`：断言随新资产名
- `CHANGELOG.md`：0.2.3 节
- 签名方式落①（gradle 注入）：本机注入构建实测产物名 `sofatype-release.apk`，v1 三件套齐 + 指纹比对通过；无 env 构建 unsigned 产物名保持 `sofatype-release-unsigned.apk`（本地装机路径不破坏）

## 验收

1. **产物签名**：CI 产物 `keytool -printcert -jarfile` 显示发布章指纹；`unzip -l` 含 META-INF 签名条目。
2. **发布链**：Release 流水线绿；资产 `sofatype-0.2.3.apk` 可下载、sha256 与 Release 页一致；本地空 env 构建 `assembleRelease` 不受影响。
3. **单测**：`downloadUrl` 构造用例随新资产名全绿（`--rerun-tasks` 口径，任务全 executed + XML 时间戳为本轮产物）。
4. **真机迁章**：卸载旧包 → `adb push` + `pm install` 装签名包成功 → `dumpsys package com.sofatype.ime` 实测 versionName=0.2.3、versionCode=5、`pkgFlags` 无 `DEBUGGABLE` → 收尾恢复 default IME 三条目态 → 真源检查更新 UP_TO_DATE（T104 同款口径）。
5. **应用内更新正向全链**：mock/注入通道或下一次真实发版真源，取 logcat `UpdateCheck` 全链行 + 安装器成功 + 版本变化三证。
6. **红线**：`git status` 无 keystore / 密码痕迹；新增文档不引用不入库文件路径。
