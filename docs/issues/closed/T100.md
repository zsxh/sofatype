## 背景

2026-11-24 户主会话拍板（GitHub CI/CD 调研后逐项拍板）。仓库将推送 GitHub 公开仓库，需要 CI（构建 + 单测）与 CD（打 tag 自动发布到 Releases 页）。T94/T95 曾拍板「GitHub（Release + Actions）第三方服务例外入册」后随词包方案废止；本次为仓库本体集成，例外重新入册。调研结论与本 issue 口径均经户主逐项拍板（见「需求与口径」）。

## 需求与口径

1. **CI workflow（`.github/workflows/ci.yml`）**：
   - 触发：push / PR 到 `main`，另支持 `workflow_dispatch` 手动触发；
   - 构建环境采用**方案 B**（户主拍板）：ubuntu runner 预装 Android SDK + `actions/setup-java` 钉 **Zulu 17**（与 flake 的 JDK 发行版对齐，压小两端漂移）；CI 不装 nix，`flake.nix` 不动；
   - 任务面：`assembleDebug` + `testDebugUnitTest` + `:pinyin:test`（HANDOFF 坑 13 口径）+ `assembleRelease`；**不含** Paparazzi 视觉回归与模拟器 instrumented 测试（户主拍板；后者沿 T91 口径移交人工批次）；
   - 权限收敛：`contents: read`。
2. **Release workflow（`.github/workflows/release.yml`）**：
   - 触发：push `v*` tag；
   - 门禁：tag（去 `v` 前缀）必须与 `app/build.gradle.kts` 的 `versionName` 一致，不一致直接失败；
   - 发布说明：从 `CHANGELOG.md` 抽取包含该版本号的 `## ` 节全文作为 Release 正文；找不到该节则失败（发版前须把「未发布」节改为版本号——CHANGELOG 既有约定）；不用 GitHub 自动 diff notes；
   - 产物：`assembleRelease` 的 `sofatype-release-unsigned.apk` 复制为 `sofatype-<版本>-unsigned.apk` 上传；
   - 发布形态：**直发**（`draft` 缺省 false，户主拍板；给应用内「检查更新」将来换真实 GitHub Releases 源留顺滑路径——匿名 API 不返回草稿）；无 secrets（unsigned 阶段），权限 `contents: write`；
   - 版本递增（决策 19）仍由工程内 `versionName`/`versionCode` 人工维护，CI 只做一致性门禁，不注入版本。
3. **仓库公开**（户主拍板）：Actions 免费额度不限；unsigned 阶段无需 secrets。
4. **本地模拟（act）——已废止**（2026-11-24 户主二次拍板）：act 实跑证实本机无法全量模拟（amd64 模拟层在宿主挂载卷缺 syscall、arm64 受 aapt2 仅 x86_64-linux 限制，证据见「追加补充」），workflow 不含本地模拟分支，验证一律依赖真实推送后的 GitHub Actions；workflow 与文档中的 act 痕迹随本拍板清理。
5. workflow 文件注释为中文（构建脚本豁免代码注释白名单，沿 2026-11-22 拍板）；action 引用钉当前主版本 tag：`actions/checkout@v7`、`actions/setup-java@v6`、`gradle/actions/setup-gradle@v6`、`android-actions/setup-android@v4`、`softprops/action-gh-release@v3`。

## 方案评估

预评（实施前）：

- 影响范围：新增 `.github/workflows/ci.yml`、`.github/workflows/release.yml`；文档同步（`docs/issues/NEXT-ID.md` 取号回写、本文、`docs/HANDOFF.md` 决策速查一行、`DEVELOP.md` 补 CI/发版节）。构建脚本（gradle / flake / wrapper）零改动。
- 回归面：本地构建链路不变（`nix develop -c ./gradlew`）；CI 用 runner 工具链属新增平行通道，不影响本地口径。
- 风险与取舍：
  - 方案 B 的 JDK/SDK 由 runner 镜像决定，存在与 flake 的环境漂移（build-tools 点版本等）；Zulu 17 + wrapper sha256 钉死已压掉大头，残余漂移接受（户主知情拍板）；
  - wrapper 分发走腾讯镜像，海外 runner 全球可达；若实测慢再议（另立变更）；
  - `setup-gradle` 缓存用 basic provider（actions/cache 封装，免增强缓存专有组件）；act 环境下该步整体跳过（无缓存服务，act 兼容性差）；
  - 本地 act 实跑受 M1 架构影响：AGP 的 aapt2 maven 产物仅 x86_64-linux，arm64 容器内无法执行，实跑需 `--container-architecture linux/amd64`（Rosetta/qemu 模拟，速度折扣），验证范围如实记录。

## 追加补充

- 2026-11-24 act 本地实跑记录（验证水位如实登记，未达全量）：
  - 环境：act 0.2.97 + 宿主 Docker「Kiri」（Server 27.5.1，aarch64）；act 的 action 缓存目录 `~/.cache/act` 在沙箱外，需 `XDG_CACHE_HOME` 重定向后才能克隆 action。
  - 已实证：两 workflow `act -l` 解析通过；amd64 模拟容器内 action 克隆、checkout、setup-java 远端解析 Zulu 17.0.21、`env.ACT` 条件分流（setup-android 装 / setup-gradle 跳过）均正常。
  - 未达全量及原因：setup-java 解包 JDK 时 tar 报 `Function not implemented`（ENOSYS）。探针定位：容器内文件系统 64 MB / 512 MB tar 往返均通过，故障仅限 act 从宿主 bind-mount 进容器的 temp 卷——Kiri amd64 模拟层 + 宿主挂载卷的 syscall 缺口，act 侧无可配置绕过项。
  - arm64 原生容器路线亦不可达完整构建：AGP 的 aapt2 Maven 产物仅 x86_64-linux，arm64 容器必死于资源处理阶段。
  - 结论：本机 act 只能做 workflow 结构与 step 逻辑级验证；完整构建 / 发布链路留待首次真实推送在 GitHub 原生 amd64 runner 上验证（下条验收口径的 GitHub 侧）。
- 2026-11-24 户主二次拍板：**本地 CI（act）要求废止**。依据上条实跑证据（本地全量模拟不可达），workflow 移除 `env.ACT` 条件步（ci.yml 的 setup-android 条件步、setup-gradle 的 ACT 跳过条件均删），文档同步清理 act 用法；act 实跑记录保留于本节作证据。此前「act + Docker 不进 flake」条款随之作废。
- 2026-11-24 户主三次指令：公开文件不出现本地 act 模拟相关内容。ci.yml 头部的废止说明注释、DEVELOP.md 的「本地模拟：无」句一并删除；act 相关叙事只保留在本文与 HANDOFF 治理记录中。DEVELOP.md 同轮去除了「户主拍板」措辞（决策过程语言不入公开文档）。
