## 踩过的坑

1. **主线程回执写 socket → StrictMode `NetworkOnMainThreadException` → IME 进程崩溃、连带宿主 Activity（同进程）**：首版 ack 回发直接在主线程（Manager 主线程块内调 `sender.send`）写 socket，debug 构建默认 StrictMode 网络检测直接抛异常，主线程死亡 → 整个 app 进程（含 IME 服务与 SettingsActivity）崩回 launcher；手机端无回执、草稿未清空（该轮失败状态截图 `screenshots/T16/superseded/browser/after-A-03-after-commit.png`、`screenshots/T16/superseded/tv/after-tv-02-committed-keyboard.png`，桌面 launcher 崩溃画面）。修复：`ConnectionWriter` 单线程写通道，全部帧写投递 writer 线程（同步等待写完返回，保住 TextThenClose 与「回执先于 stop」时序）；教训——**WS 主动回发通道的设计必须默认「调用线程不可控」**，网络 IO 永远下沉专用线程，不能假设「小帧写 TCP 缓冲不阻塞就不踩 StrictMode」。
2. **BACK 隐藏键盘后活动窗口 pan 动画期间 tap 落空**：键盘弹出时宿主窗口上移、隐藏时下移，动画未完成时按旧坐标 tap 会点空（场景 B 首次 fill 未生效、输入框空）；操作前先 `uiautomator dump` 取当前坐标再 tap，BACK 后留足动画时间（2s）。
3. **`adb emu redir add` 正确语法是单参数 `tcp:<hostport>:<guestport>`**（模拟器 KO 提示补全）：写成 `tcp:H tcp:G` 两参数报 bad redirection format；且宿主端口已被 `adb forward` 占用时 redir 报「port probably used by another program on host」——同一端口 forward 与 redir 二选一，本服务场景只监听 `10.0.2.15` 不监听设备回环，`adb forward` 不可达，应只用 redir。已补录 `local/DEV-GUIDE.md`。
4. **uiautomator dump 偶发返回 stale 快照**：一次 dump 的 `text` 与屏幕实况不符（BACK 后重新 dump 即正常），原因未查明；关键断言（文本内容 / 选区）优先用截图目视核对，dump 只作辅助。
