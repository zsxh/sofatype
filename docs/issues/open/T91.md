## 需求与口径

1. **L1 · JVM 集成测试层**：补跨模块链路用例——拼音引擎→组合→IC 上屏全链（真实词库产物，断言候选序与提交结果）；远程服务 HTTP/WS→消息解析→缓冲→策略→注册表全链；设置页路由→更新检查→解析→安装渠道→收据全链。并入既有测试任务（`testDebugUnitTest` + `:pinyin:test`），沿用 `--rerun-tasks` 强制实跑口径。
2. **L2/L3 · instrumented 场景层（2026-11-19 修订：执行与断言上设备）**：场景定义一份、模拟器与真机两环境共用——androidTest 源集（UiAutomator）内执行与断言：`UiDevice.pressKeyCode` 注入、`executeShellCommand` 读 `ImeKeyTrace` 与 logcat、截图与黄金图对比（`Bitmap.sameAs`，黄金图按设备分目录）。宿主仅薄 wrapper（python3 + adb，落 `tools/`）：冷启 / 装机 / `ime set` 核对 / `am instrument` 启动 / 收报告 / 显式收尾；真机专有环节（保活循环、安装许可 tap 代点）在 wrapper。已知模拟器假象（tap 收起失效、渲染滞留旧帧）入白名单不误报。
3. **L3 · 真机功能验收回归**：同一 instrument 场景集映射 MiTV4，宿主 wrapper 内置前置核对（默认输入法、保活循环）与安装许可代点，证据自动落 `screenshots/T91/`（或对应 issue 子目录）。**真机执行一律先询问户主，同意后才跑。**
4. **场景清单范围**：键盘显隐、组合态/候选、中英与大小写/全半角切换、删除节奏、BACK 二次退出、隐藏态键码透传、远程模式配对（Obscura 无头浏览器模拟手机端）、设置页、检查更新（`serve_mock.py` 起桩）。
5. **诚实边界**：微信内核、真实遥控器、摄像头实拍扫码不自动化，保留人工抽查；本 issue 不含性能度量（归 T92）。
6. **工具约束（2026-11-19 修订：测试域解除零依赖约束）**：允许引入第三方测试库，仅 test / androidTest / 构建插件作用域，不进产品 APK。拟引入：androidx.test（core 1.5.0 / runner 1.5.2 / rules 1.5.0 / ext:junit 1.1.5）+ `androidx.test.uiautomator:uiautomator:2.3.0`（minSdk 18，API 23 可用）；Paparazzi 1.3.x（试点，版本以实施时兼容 AGP 8.2.2 为准）。命令行工具仍先进 flake 再用；宿主 wrapper 只依赖 flake 内已有工具（python3 / adb / obscura / emulator）。
   **依赖可重现（2026-11-19 追加拍板）**：maven 库依赖不进 flake，以 Gradle 原生机制等效保证——`gradle/libs.versions.toml` 版本目录统一声明（含存量 junit / zxing / timber 一并纳入）+ `dependencyLocking { lockAllConfigurations() }` 锁文件随提交（插件 classpath 锁的 AGP 兼容性实施时验证）+ `gradle/verification-metadata.xml` 全量 SHA-256 校验、构建默认 strict。
7. **视觉回归试点（2026-11-19 拍板纳入）**：Paparazzi 试点键盘布局 JVM 渲染视觉回归（列节奏 / 键面两态 / 配色 token）；layoutlib 渲染与真机存在差异，试点结论另报户主拍板是否转正。

## 方案评估

影响范围（预评）：`app/src/androidTest` 新建源集（instrumented 场景层）；`tools/` 薄 wrapper 脚本；`app/src/test`、`pinyin/src/test` 新增用例；Paparazzi 试点含 Gradle 插件与快照用例。产品代码 `app/src/main` 不动；`flake.nix` 不动。首次拉取 maven 依赖需网络，与词库「构建零网络」门禁无关。

依赖可重现（预评）：maven 库类依赖无法有效进 flake——nixpkgs 无对应包（JMH 无 nixpkgs 打包，androidx / Paparazzi 无表达式）；gradle2nix 实验性且停更、对 AGP 支持差；本地 maven 仓库 derivation（预取全部传递依赖 + `file://` 仓库）可行但依赖变更全量重算、AGP 升级易碎，不采用。改为版本目录 + 依赖锁 + 校验和验证（口径 6）。

回归面：既有单测口径与产物不受影响；脚本操作遵守 `local/DEV-GUIDE.md` 全部纪律（HOME 分向、注入节奏、隐藏态判据、收尾清理）。

风险与取舍：真机自动化脆弱（安装许可只吃 tap、夺回链、自动清杀）→ 脚本失败即停、不轰炸重试；模拟器假象 → 断言以逻辑层为准、白名单管理。取舍：接受微信内核 / 遥控器 / 摄像头扫码段不自动化。

运行节奏（拍板口径）：L1 + L2 可在每个 issue 实现后自动执行并汇总报告；L3 及一切真机操作先询问户主。

## 验收

- L1：新用例并入 `testDebugUnitTest` + `:pinyin:test`，`--rerun-tasks` 全绿（任务全 executed + XML 时间戳为本轮产物）。
- L2：模拟器一轮完整跑通，输出场景 × PASS/FAIL 报告落盘；已知假象白名单核对无误报。属「模拟器已验证」。
- L3：真机一轮跑通（**执行前先询问户主**），证据（截图 / trace / dumpsys 摘要）落 `screenshots/T91/`。属「真机已验证」。
- 真机批次顺带覆盖模拟器白名单场景在真机上的对应行为（tap 收起、键码收起通道）。
