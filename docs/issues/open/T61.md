## 目标

字母键盘行 4 功能键（[空格]、[.com]、[→]）聚焦时按「上」方向键，焦点移动到对应上行可达键位，与同列「下」方向行为对称；其余焦点导航路径不回归。

## 改动

未开工。预计改动集中在焦点导航算法的 UP 方向搜索逻辑；实现前先复现与定位，按实际实现回填本节。

并案排查（2026-11-12 户主确认）：本条与 T58（符号键盘半角 [0] 与 [*] 间焦点不能左右直达）同属 FR-A11 焦点导航缺陷。修复与验收仍按各自 issue 独立收口，不合并验收口径。

并案排查结论（2026-11-12，T58 施工轮同实例执行）：不同源，且本条症状在当前工作区代码 + 冷启实例上不复现。T58 根因在 FocusNavigator 空格位寻路语义，本条三键（[空格] [.com] [→]）UP 路径不经过任何空格位，模型层单测（FocusNavigatorTest.explicitCriticalPathsLocked）本就锁定三键 UP 均有落点。同轮冷启实例复测（API 34）：DPAD 注入通道三键 UP 均正常移动（`dot_com UP -> digit_7`、`space UP -> symbols`、`cursor_right UP -> u`）；tap 聚焦通道（tap 聚焦 [空格] 后 UP）同样正常（`space UP -> symbols`）。证据 screenshots/T58/t61-*.png（明细见 open/T58 并案排查结论节）。T56/T57 两个已提交改动均未触及导航链路，不构成修复来源；原观测（T56 改前取证）疑似当时实例状态因素，待查。处置建议：开工前先冷启实例复现，仍不复现则按「当时实例状态待查」口径与户主确认后再定。
