## 目标

消除隐藏态（输入窗未显示）按 OK 键的必崩路径：`SofatypeImeService` 隐藏态 OK 分支调用 `requestShowSelf(int)`，MiTV4 真机 API 23 框架该调用不可达，抛 `IllegalAccessError` 致 IME 进程崩溃。治理后该分支不再崩溃，键盘正常唤起或安全降级；用户可见行为 = 「按 OK 键盘不来且进程崩」消失。

## 改动

### 现状（2026-11-18 T85 取证在案）

- 崩溃签名：`IllegalAccessError` @ `SofatypeImeService.kt:991`（`dispatchKeyDown` ← `onKeyDown`，「swallowed（输入窗隐藏态）→ requestShowSelf」分支）。
- 证据：crash 缓冲 10 条 FATAL 全部同签名，时间戳 2026-11-18 17:37–19:36（户主晚间真实使用触发）：`screenshots/T85/logs/t85-crashbuf-ts.log`（gitignore 不入库；归档前如需留存可转录关键行入本 issue）。
- 危害链：每次崩溃 = IME 进程死亡 = 下次弹键盘冷启 + 词库懒加载 = 一次 1 秒级首键尖峰（放大 T85 问题）；用户可见「按 OK 键盘不来」。

### 拍板定稿（2026-11-18 户主拍板 = 方案 A 分层兜底；PRD 决策 67 / 68；当日 dev-review 流程开工）

- 修复结构 = 分层兜底（决策 67）：①第一层保留 `requestShowSelf`，调用点窄捕获 `IllegalAccessError` / `LinkageError`；②第二层 `onShowInputRequested` veto 复检（保留 T38 收起抑制窗语义）通过后走 SDK 公开本地唤起通道（`showWindow`）；③第三层再失败 trace 留痕 + 不崩。每层写 `ImeKeyTrace`。正常框架行为零变化。
- 否决项：直改本地通道（须重写 T59 拍板 3 断言 + 放弃状态同步）；反射直连 IMM（token 私有字段 + targetSdk 34 隐藏 API 限制）。
- 验收线收紧（决策 68）：PASS 仅当真机隐藏态按 OK 键盘实际唤起；「仅不崩、键盘不来」视为未达标上报户主再议。
- 单元测试覆盖隐藏态 OK 分支不崩与降级序列；真机回归「隐藏态按 OK」场景。

## 原因

T85 真机取证（2026-11-18）发现独立于词库加载的崩溃缺陷：crash 缓冲 10 次真实使用崩溃同签名在案，持续制造额外冷启并放大首键尖峰频度。户主拍板立项（编号顺延 T86）、暂缓处理，T85 流程不受扰。

## 验收（2026-11-18 决策 68 收紧后口径）

- 真机（MiTV4）隐藏态按 OK：**键盘实际唤起（PASS 线）** + crash 缓冲零新增同签名 FATAL + T38 收起抑制窗语义零回归；
- 单测全绿 `--rerun-tasks`（覆盖隐藏态 OK 分支不崩 + 降级序列 + T38 veto 语义保留）；
- 模拟器（API 34）逻辑回归：第一层路径与既有语义零变化；
- 交叉验证：该缺陷修复后冷启频度仅余系统清杀因素；
- 全层兜底失败「仅不崩、键盘不来」= 未达标，上报户主再议，不判 PASS。

## 踩过的坑

- 真机 API 23 MiTV 框架对 IME 的 `requestShowSelf(int)` 调用抛 `IllegalAccessError`（模拟器 API 34 未复现——模拟器只做逻辑回归口径的又一实证）。
- crash 缓冲时间戳跨采样会话留存：本轮采样停止后数小时的户主真实使用崩溃仍可在取证时回捞（缓冲未轮转前提下）。
