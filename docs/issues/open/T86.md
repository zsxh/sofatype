## 目标

消除隐藏态（输入窗未显示）按 OK 键的必崩路径：`SofatypeImeService` 隐藏态 OK 分支调用 `requestShowSelf(int)`，MiTV4 真机 API 23 框架该调用不可达，抛 `IllegalAccessError` 致 IME 进程崩溃。治理后该分支不再崩溃，键盘正常唤起或安全降级；用户可见行为 = 「按 OK 键盘不来且进程崩」消失。

## 改动

### 现状（2026-11-18 T85 取证在案）

- 崩溃签名：`IllegalAccessError` @ `SofatypeImeService.kt:991`（`dispatchKeyDown` ← `onKeyDown`，「swallowed（输入窗隐藏态）→ requestShowSelf」分支）。
- 证据：crash 缓冲 10 条 FATAL 全部同签名，时间戳 2026-11-18 17:37–19:36（户主晚间真实使用触发）：`screenshots/T85/logs/t85-crashbuf-ts.log`（gitignore 不入库；归档前如需留存可转录关键行入本 issue）。
- 危害链：每次崩溃 = IME 进程死亡 = 下次弹键盘冷启 + 词库懒加载 = 一次 1 秒级首键尖峰（放大 T85 问题）；用户可见「按 OK 键盘不来」。

### 计划改动（开工时定稿；户主已拍板暂缓处理，处理时间另定）

- 候选方向：① 隐藏态唤起改走 API 23 可达通道（如 `showView` 系 / 重新绑定会话，开工时按框架实测拍板）；② 分支兜底（异常捕获 + 焦点 / 会话重建通道）。
- 单元测试覆盖隐藏态 OK 分支不崩；真机回归「隐藏态按 OK」场景。

## 原因

T85 真机取证（2026-11-18）发现独立于词库加载的崩溃缺陷：crash 缓冲 10 次真实使用崩溃同签名在案，持续制造额外冷启并放大首键尖峰频度。户主拍板立项（编号顺延 T86）、暂缓处理，T85 流程不受扰。
