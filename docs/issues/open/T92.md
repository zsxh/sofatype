## 背景

2026-11-19 户主 GUI 拍板（与 T91 同批拆分立项）：性能测量采用**方案 A「应用内 debug 门控埋点 + 设备侧计时」**。理由：验收机无线 adb 延迟 0.4~40s 剧烈抖动，宿主侧计时不成立；纯外部测量存在终点盲区（无候选发布、无 WS 收帧、无上屏成功时间戳），E2E 指标不可测。同日拍板：需要真机验证的操作一律先询问户主。

现状：PRD `docs/PRD_20261104.md` 第 8 章 4 项性能预算（键帽反馈 ≤100ms、候选刷新 ≤200ms、手机编辑→TV 显示 ≤300ms、扫码→可输入 ≤3s）与非激活零 CPU 均无回归判据。

## 需求与口径

1. **测量方案 = 方案 A**：产品代码新增 `PerfTrace` 埋点助手（debug 门控，实现同 `ImeKeyTrace` 的 `trace()` 模式），三段跨度计时：
   - `onKeyDown` → 该键引发的视图绘制完成（键帽视觉反馈）；
   - 键码进入 → 候选列表发布（候选刷新）；
   - WS 收帧 → 上屏成功写入 IC（跨屏端到端 TV 段）。
2. **隐私红线**：埋点只输出耗时与计数（logcat `PerfTrace` 行），不记录任何输入内容。
3. **E2E 手机段**（页面打开→可输入 ≤3s）：宿主侧 Obscura 驱动 H5 页测量该分段；摄像头扫码段不自动化，以二维码图人工/解码核验替代；指标口径 = 手机段 + TV 段之和 ≤ 3s。
4. **判定口径**：每指标每轮 N≥20 次采样，取中位数与 p95；判定 = 预算绝对值达标 且 较基线中位数劣化 ≤20%；任一不满足即 FAIL。
5. **基线管理**：基线 JSON 入 `docs/perf/`（一次真机基线批次采集，文件含环境指纹：uptime / meminfo / 前台态）；**基线重定须户主拍板**。
6. **真机专用**：模拟器数据不作为性能结论（既有口径：模拟器只做逻辑回归）；真机执行与基线采集批次一律先询问户主。
7. **注入与走查纪律**（沿用 `local/DEV-GUIDE.md` / 设备档案）：≥2s 注入节奏防 IC 丢键；保活循环防清杀；跑前核默认输入法、跑后恢复设置态；非激活零 CPU 用 `dumpsys cpuinfo` / `top` 外部采样。
8. **已排除**：Macrobenchmark（理由修正：benchmark-macro minSdk 23、可跑 API 23，排除依据是指标体系与 IME 生命周期不匹配——按键→上屏跨度仍须方案 A 埋点；非 API 支持线问题）；Espresso / Robolectric / microbenchmark 不引（跨窗口归 UiAutomator；代码库纯 Kotlin 可测风格；与 JMH 对纯 Kotlin 组件重叠）。
9. **JMH 引擎性能地板（2026-11-19 拍板纳入）**：`:pinyin` 模块 JMH 基准（全拼 / 缩写 / 混合查询、分词），依赖 `org.openjdk.jmh:jmh-core:1.37` + `me.champeau.jmh` 插件 0.7.x，仅基准作用域；宿主侧每次提交可跑，秒级暴露算法劣化，不必等真机批次；引擎基线随首批运行入 `docs/perf/`，劣化阈值试点后另定。依赖可重现同 T91 口径 6：版本目录 + 依赖锁 + SHA-256 校验，jmh-core 与插件入锁与校验清单，不强行 nix 化。
10. **预算判定上设备（2026-11-19 修订）**：预算 PASS/FAIL 断言在 T91 instrument 测试内设备端完成（`executeShellCommand` 读 `PerfTrace` logcat）；宿主脚本降级为采样编排与报告汇总。

## 方案评估

影响范围（预评）：`app/src/main` 新增 `PerfTrace` 助手与三处门控埋点；`app/src/androidTest` 新增预算断言用例（依赖 T91 instrumented 层）；`:pinyin` 新增 JMH 基准（插件与依赖仅基准作用域）；`tools/` 采样编排与报告汇总脚本；`docs/perf/` 基线文件（含 JMH 引擎基线）。

回归面：埋点常量门控，release 行为不变（验收 = release 构建照常 + StrictMode 口径不变）；既有 `ImeKeyTrace` 行为不变；埋点 span 端点不改变既有代码路径语义。

风险与取舍：埋点自身开销（`SystemClock.nanoTime` + 字符串拼接）→ 仅 debug 门控路径存在；测量噪声（自动清杀 / 注入病理窗口）→ 多轮中位数 + 环境指纹记录 + 异常换时段复测判真伪。取舍：接受产品源集内少量门控测量代码，换取四项预算全部精确可测。

运行节奏：真机性能批次随真机批次执行；**执行前先询问户主**。

## 验收

- **埋点**：debug 包 `PerfTrace` 行可观测且内容零泄漏核对；release 包埋点路径不进产物（构建产物抽查）。属「模拟器已验证」（逻辑链）。
- **基线**：一次真机基线批次产出 `docs/perf/baseline-mitv4.json`（**执行前先询问户主**），四项指标含中位数 / p95 / 环境指纹。属「真机已验证」。
- **判定脚本**：对基线 JSON 输出对比报告（指标 × 中位数 / p95 × PASS/FAIL）。
- **收口**：四项预算判定全绿为真机 PASS；任一 FAIL 如实记录并复测定位。
