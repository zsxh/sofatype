## 目标

## 改动

Round 1 定位（2026-11-11，dev，模拟器 emulator-5554 / API 34 / 1920×1080；包=debug 变体 `com.sofatype.ime` 0.1.0(1)，sha256 `e919ef34…efd245f`，与 T53 真机装机包同 hash；测试输入区可见——决策 21 debug 门控）：

- **复现链（模拟器，全部单键单条注入）**：装包 + `ime set` → `am start` 设置页（模拟器入口键盘不自动弹出，mInputShown=false；真机坑 18 为自动弹出）→ tap test_input 弹键盘（mInputShown=true）→ BACK 收起（keyevent 4）→ 死态成立。
- **死态探针（BACK 路径）**：OK(23) / DPAD 19·20·21·22 / BACK(4) 六键全部到达 IME（trace `onKeyDown keyCode=… focus=null`）并被消费：OK → `swallowed（输入窗隐藏态）`；宿主零反应——focused 节点恒为 test_input、文本不变、`mCurrentFocus` 恒 SettingsActivity、Activity 不退出（topResumedActivity 在案）、前后截图逐字节同图。
- **完成 键收起路径对照**：同死态；守卫过期 35s 后 OK 仍吞、无唤起 → 两收起路径死态一致。[下屏] 键与 [完成] 键走同一收起函数（源码同路，SofatypeImeService 两处 KeyAction 同调 hideSelfAfterKeyDispatch），未单独实测。
- **恢复通道（模拟器实测）**：①tap test_input → 键盘重弹、键全部恢复；②HOME → 回 launcher（系统层按键不经 IME 分发）；③负面结果：tap「检查更新」可触发（UpdateCheck 手动检查发起/结果双日志）但视图焦点仍滞留 test_input、键仍被吞——tap 其它控件不恢复键导航。遥控器无 tap 通道：两条收起路径下按键内无恢复路径（OK 均不唤起）。
- **定性**：应用侧（非 T50 同族）。判据四条：窗口焦点正常（mCurrentFocus=SettingsActivity）／tap 派发存活（UpdateCheck 双日志）／输入会话仍绑定（dumpsys input_method mCurClient、mCurMethodId=sofatype，全文留证）／全部键码到达 IME 并被服务 onKeyDown 消费（ImeKeyTrace 逐键在案）。T50 同族形态（tap/键全不达、无 trace）与本轮证据相反。
- **机制链**：收起后视图焦点滞留 test_input（设置页无焦点接管，T20 P1「焦点动态切换」未做）→ 输入会话不终结 → 遥控键先路由进隐藏态 IME → `dispatchKeyDown`：BACK/方向键无条件消费（两分支 return true），确认键走 T38 隐藏态吞键 → 宿主收不到任何键 → 全键无响应（含 BACK 退出设置页失效）。
- **触发条件**：宿主 EditText 持焦点（输入会话在）+ 键盘收起（BACK 或 [完成] 任一路径，实测）。真机坑 18 口径下进设置页即自动弹键盘，BACK 收起即触达。
- **影响范围**：设置页 + 任意宿主同型场景（EditText 焦点 + 收起）。真机同族旁证（既有档案）：closed/T53 坑 1（真机 BACK 收起后 CENTER 被吞无唤起，两发 3 分钟间隔同结果）。
- **修复方向建议（拍板归户主，本轮零代码改动）**：①设置页焦点接管（收起后焦点移出 test_input，T20 P1 落地）；②IME 隐藏态按键消费语义重审（BACK/方向键隐藏态是否透传宿主，与 T38 防直落字符守卫回归一并核）。平台挂账（T39 先例模式）不适用——非平台行为。

对 lead 静态初诊线索的实测修正（lead 初诊 → dev 实测修正，2026-11-11）：

- 线索「OK 仅在 T38 收起抑制窗（800ms）内被吞」不准确：实测为输入窗隐藏态**无条件吞**（收起后 35s 仍吞）；800ms 窗只作用于宿主 show 请求裁决（onShowInputRequested）。
- 线索「DPAD 左右仅光标移动」不成立：DPAD 根本不到宿主（trace 证实被 IME 方向分支消费），无光标移动。
- 线索「T52 无回归嫌疑」：本轮未复测 T52 键面行为（与收起链无涉），维持原口径不作结论。

## 踩过的坑

1. **模拟器实例时钟偏移（2026-11-11 Round 1 实测）**：`-no-snapshot` 冷启实例时钟比宿主慢约 3 小时（guest 13:33 ↔ 宿主 16:33）：ImeKeyTrace 等设备侧日志时间戳按 guest 时钟读，与宿主时间对照先 `adb shell date` 核。仅本轮实例观测。
2. **`adb emu kill` 须 HOME 指向 `.emulator-adbhome`（2026-11-11 Round 1 实测）**：不带 HOME 重定向执行报 `authentication token does not match ~/.emulator_console_auth_token` 杀不掉；重定向后 `OK: killing emulator` 生效。收尾判据：5554/5555 无 qemu 监听 + `adb devices` 空。已同步 local/DEV-GUIDE.md 1.5。
3. **tap「检查更新」不恢复键导航（2026-11-11 Round 1 实测，负面结果留证）**：死态下 tap 按钮可触发点击（UpdateCheck 双日志）但视图焦点滞留 test_input、输入会话不终结，随后的 OK 仍被隐藏态 IME 吞——恢复键导航只能 tap 输入框（键盘重弹）或 HOME 逃逸。
4. **焦点接管首版落空：触摸模式 + 窗口级会话（2026-11-11 Round 2 实测）**：①tap 弹键盘使窗口进入触摸模式，`Button.requestFocus()` 在触摸模式对 `focusableInTouchMode=false` 控件静默失败——须用 `requestFocusFromTouch()`（临时解除触摸模式完成移焦）；②API 34 输入会话是窗口级绑定（`mCurClient` 随窗口焦点存活）：视图焦点移出编辑框后遥控键仍先路由进隐藏态 IME（`mCurEditorInfo` 已空、键照走）——焦点移出只解「编辑框滞留」，不解「键被 IME 消费」，后者是 T59 面；宿主侧合法前置通道=根视图 `dispatchKeyEventPreIme`。
5. **走查自污染：force-stop launcher 与 am start 回前台（2026-11-11 Round 2 实测）**：①`am force-stop com.google.android.tvlauncher` 后系统约 2 秒自动重启 launcher（LAUNCH_SINGLE_TASK 抢前台，指纹=logcat `START ... tvlauncher/.MainActivity from uid 10079`），污染前台判定；②`am start` 对已存在任务只是回前台（无新 onCreate）——logcat -c 后应用日志空≠应用没跑。已同步 local/DEV-GUIDE.md。
