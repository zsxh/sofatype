## 目标

组合态按「←」（网格左移光标）后 composer 与输入框状态保持一致：框架落定组合时 composer 同步终结；该路径后删除键直接生效，不出现幻影组合吞键、不闪插字母；与 T48 DEL 拦截分支、T44 选词复位、T22 连删互不回归。

## 改动

待实现（定位归 dev，不预设）。行为级观测（2026-11-10 T27 重启批次真机，review-qa）：

- 组合「ke」激活态（下划线在）按网格「←」：框架结束组合、字母落定正文（ke 变普通文本）、光标左移一格——composer 不知情，仍持组合串「ke」（幻影）。
- 此后 DEL（键码 67）前两针被幻影消耗：DEL#1 经 T48 拦截分支（组合非空判定取 composer 幻影值）走 performDelete → composer ke→k → `setComposingText("k")` 在光标处**插入**字母 k（正文 ke→kke，受控轮 dump+截图实锤；首轮非受控观测中该写入未可见落地，两轮差异如实标注）；DEL#2 composer k→空、`setComposingText("")` 删掉插入字母（正文回 ke，伴随 total=0 装载行=composer 幻影态 trace 指纹）；DEL#3 起 composer 已空走 IC 直删才真正删正文。
- 嫌疑方向（供 dev 参考）：← 键路径落定组合时 composer 未同步终结（与 T48 同族=composer/IC 同步问题，但触发路径不同：T48 是删除键码未拦截，本缺陷是 ← 落定组合未同步；T48 的 DEL 拦截分支在本序列被幻影组合态误导）。

## 原因

T27 重启批次真机复验发现（2026-11-10，review-qa，户主拍板立号）：组合态移光标是常见编辑操作，触发后用户感知=「← 后删除第一下不删反可能闪字母、第二下白按」，需多按才生效；可自愈、无永久残留、正文最终一致。严重程度初判低-中。2/2 受控复现 + 1 次非受控观测（A2 保活针偏航事故链，额额额ke→额额额e）。
