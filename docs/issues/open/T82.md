## 目标

从 SofaType 设置页返回/退出后，系统默认输入法保持本 IME，不再被自动夺回搜狗；若平台夺回链无法在应用侧根除，至少提供用户可感知、可一键恢复的通道。产出含两段：真机诊断取证（补齐坑 5 挂账的指纹核验）+ 依诊断拍板的修复实施。

## 改动（计划，开工后按实际更新；修复方向需户主拍板）

- **①诊断先行（真机 MiTV4；方案已定稿入档，开工须户主批准，当前未开工）**：复现「设置页 BACK 二次退出 → 夺回」链，全窗 logcat 抓 `Force stopping com.sofatype.ime` 指纹与杀进程发起方、退出前后 `default_input_method` 与 IME 进程 pid 双读——补齐 2026-11-13 T54/T62 批次挂账的指纹核验，定性「退出沿 IME 进程死亡」的直接触发（是设置页前台进程清理连带，还是 IME 系统窗口/解绑链触发，决定方案 A 是否有效）。诊断范围：BACK 二次退出主路径 ≥3 轮 + HOME 退出 / 设置子页返回变体各 ≥1 轮 + 键盘窗口显示态对比 1 轮。
- **②修复方向（依诊断拍板，主候选 + 兜底）**：
  - **主候选 A · 设置页拆独立进程**：设置页相关 Activity（`SettingsActivity` / `LogSettingsActivity` / `LogViewerActivity`）迁 `android:process=":settings"`——平台清杀前台设置页所在进程时不再连带 IME 进程 → 不触发 force-stop 包事件 → AOSP 6 `IMMS.PackageMonitor.onHandleForceStop` 重置链（T39 源码实证）不发生。T39 已核设置页自包含、迁移成本近零；开工前重核 T39 之后新增的日志设置 / 查看页与 debug 子系统跨进程面。
  - **兜底候选 B2 · 设置页检测引导**：设置页 onResume 读 `default_input_method`（公开读取）≠ 本 IME 时提示 + `showInputMethodPicker()`（公开 API 零权限）一键选回；覆盖一切夺回链（屏保强杀坑 9 / 清理者坑 10 / 本链）的恢复通道，不覆盖「下次打字」时刻。
  - B1 自动写回（`WRITE_SECURE_SETTINGS` adb 授权）与维持现状（C）：按诊断结论再议。
  - 决策 37（2026-11-09「挂账观察」）的前提「真实主场景不回退」已被户主实际使用证伪，无论选哪个方向均需修订条款入册 PRD 第 12 章（编号顺延）。

## 原因

2026-11-17 户主真机使用反馈：从 SofaType 设置页返回/退出，系统输入法自动切成搜狗。既有链路：坑 5（2026-11-08，杀 IME 进程夺回）→ 2026-11-13 T54/T62 真机批次「设置页 BACK 退出伴随夺回」3/3 稳定复现、每次伴随 IME 进程更换（HANDOFF 遗留观察挂账，机制未查明）→ T39 评估（2026-11-09）定性两段式链路（平台 force-stop 类动作 × AOSP 原生重选系统默认 IME）并按「真实主场景不回退」拍板挂账观察（决策 37）。本次为真实使用命中该链，前提推翻，户主报告即重新立项治理。
